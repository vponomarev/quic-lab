# Multiple VPN — экспериментальный Android-клиент

Версия 0.7.0-dev, работа без проверки на физическом телефоне. Серверный протокол
не меняется: текущие QUIC/HTTPS gateway и AmneziaWG совместимы. До проверки на
телефоне APK не заменяет опубликованную студенческую сборку.

## Настройка

1. Импортируйте отдельные профили серверов и настройте каждому транспорт.
2. Домашнему профилю задайте режим «network routing» и нужные IPv4 CIDR.
3. Второму профилю задайте выбранные приложения; доступен общий или собственный список.
4. Откройте «Настройки VPN → Несколько VPN одновременно», включите multiple
   и отметьте нужные профили. Стрелки меняют их приоритет, сверху вниз.
5. Выберите DNS-профиль с доступным DNS-сервером. По умолчанию это первый
   включённый профиль; если домашний gateway не пропускает публичный DNS,
   явно выберите другой профиль или задайте доступный ему DNS в настройках.
6. Запустите VPN и подтвердите системное разрешение Android.

Один системный VpnService/TUN обслуживает все профили. Приложение определяет UID
владельца нового TCP/UDP-потока через ConnectivityManager.getConnectionOwnerUid.
Правила проверяются в порядке профилей; первое совпадение выбирает выход.
Подсети не получают скрытого приоритета: домашний профиль поставьте выше профиля
приложений, если он должен побеждать при пересечении.

Несовпавший IPv4-трафик отправляется напрямую через защищённые от рекурсии
сокеты. При достижении правила приложений с неизвестным UID поток блокируется,
а не уходит напрямую. Приложения с общим UID получают общий маршрут.
Профиль all apps перехватывает всё оставшееся, exclude — всё кроме заданных UID.
Сам QUIC Lab исключён из TUN. IPv6 для захваченных приложений заблокирован.

Каждый профиль имеет отдельное подключение, сетевой контроллер и метрики.
Остановка профиля отменяет его текущие потоки и блокирует новые по его правилам;
нижестоящий профиль и direct не являются резервным выходом. Повторный запуск
создаёт новые потоки; завершённые TCP-сессии не возобновляются. Окончательно
оборванные подключения повторяются контроллером multiple с интервалом около 5 с.
Миграция живого QUIC-соединения остаётся задачей существующего VpnSession.

Настройки и порядок фиксируются на время работы: для изменения остановите VPN.
Независимая остановка/возобновление профилей доступна на экране multiple.

## DNS и диагностика

В первой версии один явно выбранный профиль обслуживает обычный DNS TCP/UDP
на порт 53, независимо от UID системного резолвера. Адрес назначения DNS не
переписывается: системный DNS берётся из выбранного профиля, собственные запросы
приложений к другим DNS на порт 53 идут через тот же профиль. Его остановка может
лишить DNS все приложения — это ожидаемо, прямого fallback нет.
Private DNS/DoH не являются обычными запросами на порт 53; split DNS и Fake IP
отложены. Не обещается распределение зашифрованного DNS по исходным приложениям.

На главной странице и экране multiple показываются статус, транспорт, свежий
RTT, TX/RX rate и счётчики текущего подключения каждого профиля. Exit IP в multiple
пока отключён, чтобы не показывать один адрес как общий для разных выходов.
Диагностический журнал содержит profile_id, UID, назначение, выбранное правило,
route_selected/route_blocked и ошибки отдельного туннеля; ключи не включаются.

## Выполненная автономная проверка

- Go-тесты приоритетов, пересечений, unknown UID, exclude и валидации.
- Linux race-тесты: одновременно QUIC и HTTPS; TCP echo, UDP через общий TUN
  для QUIC/HTTPS/direct, TCP через TUN и half-close, AWG UDP через тот же router.
- Остановка, блокировка fallback, защита direct-сокетов и игнорирование stale detach.
- Сборка Android AAR/APK, lint и компиляция instrumentation-тестов.

На телефоне ещё нужно проверить: UID TCP/UDP реальных приложений, системный DNS,
одновременный доступ приложения и домашней подсети, перестановку приоритетов,
остановку одного профиля, повторный запуск, Wi-Fi/LTE, фон/блокировку экрана,
возврат в single-profile и Echo. Android instrumentation-тест MultipleProfilesTest
подготовлен, но не запущен. Современного эмулятора в текущей среде нет.
