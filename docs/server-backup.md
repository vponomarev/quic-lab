# Резервные копии сервера

WEB: **Пользователи → Резервные копии**. Выберите «Конфигурация и доступ» или «Все данные приложения», задайте пароль и скачайте готовую копию вне VPS. Пароль сервер не сохраняет; утрата пароля означает утрату возможности восстановления.

Оба режима включают пользователей, сертификаты, ключи устройств, отзывы, MDM-привязки и настройки. Полная копия также включает историю MDM, клиентскую диагностику и захваты. Конфигурационная копия исключает историю. Конфигурация запуска AWG (`awg.json`) формируется из загруженных настроек админки; поддерживайте ручные настройки admin.json и awg.json согласованными. APK, исполняемые файлы, ОС, ACME-аккаунт/расписание, активные подключения и административные сессии не копируются. После восстановления ожидавшие MDM-команды отменяются; желаемая конфигурация и защита от повторов сохраняются.

Снимок создаётся без остановки VPN. При интенсивных изменениях или превышении секундного дедлайна закрепления файлов операция может завершиться ошибкой: повторите её позже. Упаковка/шифрование выполняются после освобождения барьера. Сервер хранит до трёх готовых копий в течение 24 часов. Параметр `backup_mib` в admin.json задаёт дисковую квоту (по умолчанию 2048 МиБ), учитывающую снимок и выходной файл. Удаление копии не обрывает начатое скачивание.

## CLI и автоматизация

CLI Linux обращается к работающему серверу через приватный Unix-сокет. Запускайте от root либо сервисного пользователя. Это тот же механизм, что и в WEB, с общим ограничением на одно задание.

```sh
sudo /opt/quic-lab/quic-lab-server backup create \
  --type full \
  --output /srv/backup-outbox/quic-lab-2026-10-10.age \
  --password-file /etc/quic-lab-backup.password \
  --json
```

Выходной каталог должен существовать; итоговый файл не должен существовать. Файл пароля — обычный файл с правами 0600, не symlink. Альтернатива — `--password-fd N`; без указания источника возможен интерактивный ввод с отключённым echo. Пароль в argv и переменной окружения не поддерживается. Защитите и храните пароль отдельно от VPS, например в менеджере паролей. Последний перевод строки в файле пароля допускается.

Результат `--json`: `format_version`, `job_id`, `type`, `created_at`, `path`, `size_bytes`, `sha256`, `server_version`. stdout содержит только результат; прогресс/ошибки — stderr. Код 0 означает готовый, полностью полученный файл. Код 2 — параметры/секрет/валидация, 3 — сервер недоступен или занят, 4 — ошибка создания/передачи/диска. При ошибке отправку не начинать. Итоговый файл публикуется без перезаписи после сверки размера и SHA-256; частичные файлы не выдаются за готовый архив.

Внешний скрипт отвечает за расписание, доставку, подтверждение доставки и ротацию внешних копий. Пример `/usr/local/sbin/quic-backup-job` (команду отправки предоставляет администратор):

```sh
#!/bin/sh
set -eu
umask 077
outbox=/srv/backup-outbox
archive="$outbox/quic-lab-$(date -u +%Y%m%dT%H%M%SZ).age"
/opt/quic-lab/quic-lab-server backup create --type full \
  --output "$archive" --password-file /etc/quic-lab-backup.password --json \
  > "$archive.json.tmp"
mv "$archive.json.tmp" "$archive.json"
/usr/local/sbin/send-backup "$archive"
```

`send-backup` — отдельная команда администратора, не часть приложения. Файл остаётся в outbox даже при ошибке доставки. Скрипт не удаляет исходную копию автоматически.

Пример service: `Type=oneshot`, `User=root`, `UMask=0077`, `ExecStart=/usr/local/sbin/quic-backup-job`. Пример timer: `OnCalendar=*-*-* 03:00:00`, `Persistent=true`. Установка и включение timer выполняются администратором отдельно; приложение расписание не создаёт. Не используйте общий CLI deadline короче длительности копирования.

## Проверка и восстановление

Сначала установите ту же версию серверного release и необходимые AWG/Xray/systemd-компоненты. Версия контейнера и версия сервера находятся в зашифрованном manifest; inspect также полностью проверяет аутентификацию архива.

```sh
sudo /opt/quic-lab/quic-lab-server backup inspect --input server.age
sudo /opt/quic-lab/quic-lab-server backup verify --input server.age
sudo systemctl stop quic-lab quic-lab-awg quic-lab-vless quic-lab-transit
sudo /opt/quic-lab/quic-lab-server backup restore --input server.age
sudo /opt/quic-lab/quic-lab-server backup restore --input server.age --yes
```

Без `--yes` restore показывает карту замены. Проверка шифрования, размеров, хешей и прикладных связей выполняется до замены. Блокировки владельцев дополнительно проверяют, что процессы остановлены. Все четыре службы удерживают общую блокировку в отдельном `quic-lab-control` StateDirectory; она сохраняется при замене данных. После аварии во время замены запуск блокируется до CLI rollback. На изолированной тестовой установке доступен `--root /path/to/installation`; это корень стандартной раскладки `/etc/quic-lab` и `/var/lib/quic-lab`, не произвольная карта путей.

Восстановление полностью заменяет конфигурацию и область данных; текущая история не смешивается с восстановленными идентичностями. Резервное прежнее состояние находится в приватном `/var/lib/quic-lab-restore/<id>/old`. Оно не зашифровано и предназначено для локального отката. Не удаляйте его до проверки восстановления. При ошибке оставьте службы остановленными и выполните показанную команду:

```sh
sudo /opt/quic-lab/quic-lab-server backup rollback \
  --journal /var/lib/quic-lab-restore/ID/journal.json
```

Старый архив возвращает доступ на свою дату: отзывы ключей, сделанные позже, могут быть потеряны. Ни restore, ни rollback автоматически не запускают службы.

Перед запуском проверьте адреса, порты, аплинк и сертификаты. Сохранённые сертификаты восстановлены как `/etc/quic-lab/cert.pem`, `key.pem` (и при необходимости `vless-cert.pem`, `vless-key.pem`). Настройте `LoadCredential=cert.pem:...` и `LoadCredential=key.pem:...` в systemd-unit/drop-in соответствующих служб на эти файлы либо установите совместимые сертификаты через ACME. Учитывайте TLS pinning старых профилей. Продление ACME на новом сервере настраивается отдельно.

Заново разместите APK из release: копия намеренно не содержит бинарники. При сохранении публичных адресов, доверия TLS и ключей устройств повторная регистрация VPN/MDM-клиентов не требуется. Затем выполните daemon-reload и запустите нужные службы, проверьте реальные подключения и получение MDM-событий.

Формат v1 — tar.gz внутри парольного age. CLI ограничивает проверку 100000 файлами и 64 ГиБ распакованных данных. Неподдерживаемые версии, опасные пути, ссылки/специальные файлы, дубли и повреждение отклоняются. Сохраняйте совместимый server release отдельно от зашифрованного файла данных.

Расшифрованный CLI staging имеет права 0700 и удаляется после проверки. После аварийного завершения остатки удаляются при следующем verify/inspect/restore того же Unix-пользователя; параллельная проверка для одного пользователя отклоняется.
