# Server exits: проверка реализации, 2026-11-04

Ветка `codex/server-exits`, база `4e2bd00`, основная реализация `c5dcd71`.
Изолированный worktree сохраняет незавершённые изменения прежней разработки.
На рабочие серверы эта версия не развёртывалась.

## Что проверено

- Каталог AWG-выходов, ACL пользователя, выбор устройства, атомарное сохранение,
  восстановление после перезапуска, конкурирующие ревизии, отзыв прав и отсутствие
  fallback при ошибках. Ответы клиентам не содержат конфигурации выходов.
- Два зашифрованных AWG-peer с пересекающимися внутренними адресами: TCP, UDP,
  DNS, ICMP, выбор выхода и отказ peer. Пакеты нативного AWG проходят через
  криптографическую проверку входа, брокер и выбранный AWG-выход.
- Идентичность bond-потоков, маршрутизация VLESS TLS/REALITY TCP/UDP через брокер,
  проверка источника AWG-пакетов, capability checks старых workers, backup/restore.
- Linux CLI выбора выхода, Windows настройки/IPC и жизненный цикл токена,
  полный WPF-набор сценариев. Android APK и lint, четыре инструментальных теста
  `ServerExitSelectionTest` и `ServiceTransferTest` на Redmi Note 9 Pro / Android 11.

Go выполнялся на разрешённом тестовом Linux-хосте `192.168.5.214` в отдельном
каталоге `/tmp/quic-server-exits-20261104`. Передавались исходники и синтетические
фикстуры. `go test` на Windows не запускался; Windows native test executables
собраны на Linux, WPF проверен локально.

## Финальное ревью и исправления

Один независимый reviewer проверил диапазон `4e2bd00..c5dcd71` и нашёл четыре
Important-замечания; Critical не было. Все четыре приняты и исправлены одним
проходом с регрессионными тестами:

1. Подтверждение смены выхода могло опередить завершение старой записи.
   Брокер, QUIC, WebSocket и логическая bond-сессия ждут завершения обработчиков.
   Тесты приостанавливают запись в старый provider и проверяют барьер отзыва.
2. Legacy transit мог держать peer-lock в другом каталоге. Named exits берут
   блокировки в `data_dir` и каталоге `transit.probe_socket`, учитывают алиасы
   каталогов и освобождают частично приобретённые блокировки при ошибке.
3. Сохранённые AWG-реквизиты требовали уже отключённый worker. Учитываются
   текущая конфигурация входа, права пользователя и неподтверждённые отзывы.
   Неудачный отзыв остаётся блокирующим; успешное применение снимает ожидание.
4. В Windows ручной ключ B после импорта A сохранял токен A. Импортированные
   управляющие данные привязаны к импортированному ключу; кеш транспорта
   обновляется при сохранении и не восстанавливает удалённый токен.

RED-логи воспроизведения и GREEN-логи исправлений сохранены локально в
`artifacts/server-exits-20261104/`, вместе с полным исходным review diff.

## Принятые решения

1. Отдельный чистый worktree сохраняет чужие незавершённые правки; интеграция
   с прежней веткой остаётся отдельной операцией.
2. Администратор выдаёт права пользователю, выбор хранится у устройства и общий
   для его входных протоколов; одна общая учётная запись не даёт независимого
   выбора нескольким устройствам без отдельных регистраций.
3. Не более 32 новых выходов, только AWG, без автоматического fallback; при отказе
   выбранного выхода соединение не работает, а не меняет маршрут без согласия.
4. Один userspace-владелец AWG и приватный брокер для workers предотвращают
   roaming peer; недоступность владельца блокирует управляемый трафик.
5. Windows требует stopped VPN, Linux — stop/select/start; бесшовной смены на
   этих платформах в первом этапе нет.
6. Default может отсутствовать; тогда требуется явный выбор. Удаление постороннего
   ID каталога не блокирует другое явно выбранное разрешённое направление.
7. Ограниченное исключение Xray `checkptr` уменьшает проверку unsafe-кода
   зависимости; проектный код и race detector проверяются полностью.
8. Зашифрованные peers в userspace netstacks заменяют kernel namespaces для
   тестов; firewall, рабочие профили и маршрутизация установки не подтверждены.
9. Выводы ревью о production firewall/routing оставлены за пределами этой
   разработки; реальная приёмка обязательна при развёртывании.
10. Upstream unsafe-код Xray не менялся; риск совместимости отмечен в пункте 7.
11. Другие providers, hot reload и failover отложены; для них потребуется
    отдельная реализация и проверка.

## Границы результата

- Приёмка использует независимые userspace netstacks, не kernel namespaces.
  Проверены реальное AWG-шифрование и пересекающиеся адреса без изменения
  маршрутов хоста. Рабочие AWG-провайдеры, firewall и реальные внешние IP требуют
  отдельной проверки при развёртывании.
- Для race-тестов REALITY отключён только `checkptr` в upstream пакетах Xray
  VLESS: их существующая unsafe-арифметика несовместима с этой проверкой Go 1.26.
  Детектор гонок работает; обычный тест проходит без исключения. Код проекта
  не освобождён от `checkptr`.
- Другие протоколы выхода, горячее редактирование каталога и failover отложены.
  Явное описание capabilities провайдера (Minor-замечание ревью) нужно добавить
  перед подключением провайдера, который не реализует весь контракт AWG v1.
- Выбор в Windows требует остановленного VPN; Linux использует описанную
  последовательность stop/select/start. Android переподключает профиль сам.
