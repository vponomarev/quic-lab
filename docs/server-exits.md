# Несколько выходов сервера

Администратор задаёт каталог AWG-выходов и разрешения пользователя. Каждое
зарегистрированное устройство выбирает свой выход из разрешённых. Выбор общий
для QUIC, HTTPS, bond, нативного AWG и VLESS этого устройства.

`server_exit_id` обозначает выход **на сервере**. Прежний `exit_id` обозначает
локальный профиль или группу клиента; эти поля независимы. Ключи удалённых
AWG-выходов хранятся только на сервере.

## Настройка сервера

Добавьте в приватный `admin.json` поле `server_exits` (не более 32 записей):

```json
{
  "server_exits": [
    {
      "id": "west",
      "name": "Запад",
      "protocol": "awg",
      "awg_config": "<полное содержимое AWG .conf с экранированными переводами строк>"
    },
    {
      "id": "east",
      "name": "Восток",
      "protocol": "awg",
      "disabled": false,
      "awg_config": "<другой AWG .conf>"
    }
  ]
}
```

Это схема, а не готовая конфигурация: замените заглушки рабочими AWG-профилями.
Каждый профиль должен покрывать `0.0.0.0/0` в `AllowedIPs`. ID начинается с
латинской строчной буквы, далее допускает строчные буквы, цифры, `_` и `-`,
до 64 символов. Зарезервированы `direct`, `legacy`, `default`.
Поддерживаются параметры AWG, которые принимает существующий клиент проекта.
Неподдерживаемый протокол или ошибочный профиль отклоняет запуск.

Изменение каталога требует перезапуска сервера. Каждый выход получает отдельный
userspace AWG engine и сетевой стек: одинаковые внутренние адреса у разных
провайдеров допустимы. Один и тот же AWG peer нельзя одновременно использовать
как несколько выходов или как старый глобальный `awg-transit`: это контролируется
общей блокировкой владельца peer. Для другой установки блокировка не действует;
используйте отдельные ключи.

Если legacy `transit.probe_socket` находится вне `data_dir`, named exits берут
блокировки в обоих каталогах. Оба каталога должны уже существовать, принадлежать
пользователю сервера и иметь права `0700`; алиасы одного каталога не создают
повторную блокировку.

В панели откройте **«Выходы сервера»**, выберите пользователя, режим
«Разрешённые выходы», разрешите нужные ID и назначьте default. Default можно
оставить пустым: тогда устройство должно явно выбрать выход. Пустой ACL
блокирует выход. Права меняются без перезапуска, текущие соединения устройств
этого пользователя закрываются.

Без политики пользователя сохраняется прежний глобальный direct/transit.
Отозванный, удалённый или отключённый выбранный выход блокируется, автоматического
перехода на другой выход или direct нет. Удаление одного ID не блокирует другой
явно выбранный разрешённый выход. Чтобы вернуть устройство в прежний режим,
администратор снимает управляемую политику, а клиент выбирает «По умолчанию».

## Клиенты

- **Android:** редактор управляемого профиля → «Выход сервера» → выбрать →
  «Применить и переподключить». Служебный HTTPS идёт через физическую Wi-Fi/LTE
  сеть с существующим учётом бюджета. Переподключается соответствующий профиль.
- **Windows:** импортировать профиль по URL/приглашению и сохранить. Остановить
  VPN → настройки → «Выход сервера» → обновить список и применить. После этого
  снова подключить VPN. Ключ управления хранится вместе с профилем под DPAPI,
  публичные ответы службы его не возвращают. Ручная замена VPN-ключа удаляет
  прежние управляющие данные; новый импорт переносит данные нового устройства.
- **Linux:** добавить в приватную конфигурацию клиента `server_control` из
  проверенного ответа регистрации:

```json
{
  "server_control": {
    "config_url": "https://control.example/api/v1/devices/DEVICE_ID/config",
    "device_id": "DEVICE_ID",
    "update_token": "<64 шестнадцатеричных символа из регистрации>"
  }
}
```

Остановите Linux VPN перед сменой, выполните команды и запустите его снова:

```sh
linux-vpn-client -config client.json -server-exits
linux-vpn-client -config client.json -server-exit west
linux-vpn-client -config client.json -server-exit default
```

Команды выводят JSON состояния без токена. Для выбора именно из ранее полученного
списка передайте `-exit-revision HASH`; без него CLI сначала читает свежую ревизию.
Эти команды не открывают TUN и не требуют root. Защитите файл конфигурации (`0600`).
Обычный AWG `.conf` или VLESS URI без регистрации не содержит ключа управления:
для выбора нужен управляемый профиль. Старые приложения используют назначенный
default; отдельный выбор без их обновления доступен через API.

## API и ошибки

`GET /api/v1/devices/{device_id}/server-exit` с существующим device bearer token
возвращает `choices`, `selected`, `effective`, `legacy`, `blocked`, `pending`,
`revision`. `POST` на тот же адрес принимает:

```json
{"server_exit_id":"west","revision":"<ревизия из GET>"}
```

Пустой ID означает default. Данные сохраняются атомарно, старые потоки закрываются,
и только затем сервер подтверждает применение. `409` требует обновить список,
`403` означает запрет, `503` — отсутствие подтверждения применения. После потери
ответа выбор мог сохраниться: сначала GET, затем осознанная повторная попытка.
Пока применение не подтверждено, новый пользовательский трафик блокируется.
Подтверждение ждёт завершения обработчиков старых потоков, включая bond и
пакетный брокер. Сохранённые ключи отключённого входного протокола не требуют
его worker; незавершённый отзыв доступа продолжает требовать подтверждения.
Недоступность upstream не отменяет сохранённый выбор: подключения завершаются
ошибкой, а не идут через другой выход.

## Обновление и резервные копии

1. Сделайте резервную копию текущих настроек и identities.
2. Обновите **все** серверные бинарники (`server`, `awg-server`, `awg-transit`,
   `vless-server`) из одной версии. Остановите старые процессы перед запуском новых:
   старый `awg-transit` не знает о новой блокировке peer.
3. Сначала запустите обновлённую установку без новых политик, затем добавьте
   каталог, перезапустите владельца и назначьте права тестовому пользователю.
4. Проверьте каждый используемый входной транспорт и фактический внешний IP.

Новые worker capability checks отвергают неподдерживающие выбор версии. Главный
сервер и workers должны работать от одного владельца приватного data directory.
Unix broker `server-exits.sock` имеет права `0600`, каталог — `0700`. Новые
маршруты ядра для named exits не создаются. Legacy AWG сохраняет прежний kernel TUN.

Резервная копия включает AWG-секреты каталога в `config/admin.json`, ACL и выбор
в `data/identities.json`. Восстановление выполняйте той же или совместимой новой
версией. Для отката на старые бинарники сначала снимите managed policies и
явные device selections на новой версии: старый код не умеет обеспечивать их.

Внешние ICMP/DNS/exit-IP используют выбранный provider. Echo адреса локального
AWG gateway и gateway RTT остаются локальными. TCP/UDP capture managed native
потоков подключён в брокере с прежними ограничениями capture для bond.

Поддержка провайдеров других протоколов, горячее редактирование каталога и
автоматический failover между выходами в этот этап не входят. Реальная установка
с пользовательскими AWG-профилями пока не развёрнута; приёмка использует отдельные
локальные зашифрованные peers, без изменения маршрутов тестового хоста.

Результаты тестов и границы приёмки: [журнал проверки](server-exits-verification.md).
