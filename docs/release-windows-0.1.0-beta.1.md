# QUIC Lab Windows 0.1.0-beta.1

Windows x64 beta. Отдельная линия выпусков: Android и сервер 0.9.4 не заменяются.

## Возможности

- Компактный GUI: подключение/отключение, TX/RX за подключение и текущая скорость.
- Редактор подключения; весь IPv4 или до 256 непересекающихся подсетей. IPv6 не изменяется.
- QUIC/HTTPS, standalone AmneziaWG (legacy), VLESS TCP с TLS/REALITY.
- Импорт по HTTPS URL: приглашение QUIC Lab, профиль JSON, AWG config, файл с VLESS URI. Изменения сначала попадают в черновик. Загрузка приглашения регистрирует устройство.
- Автоматический выбор физической сети и переподключение, DNS через туннель в полном IPv4-режиме.
- ICMP Echo и TTL/router errors для QUIC/HTTPS с совместимым сервером; ICMP через AWG. VLESS ICMP не поддерживает.
- Настройки и ключи хранятся службой под DPAPI; применение во время работы требует подтверждения переподключения.

## Ограничения beta

- Маршрутизация по приложениям ещё не реализована. Редактор списков сохраняет только черновик; он не ограничивает захват трафика. Основная архитектура описана в docs/superpowers/specs/2026-10-14-windows-per-app-tun-design.md.
- Нет kill switch, MDM и исследовательского сбора Windows. При остановке/аварии возможен прямой выход; при оставшихся маршрутах возможна временная потеря связи до очистки.
- Полный режим сохраняет специальные диапазоны, адрес сервера и существующие явные маршруты других адаптеров вне VPN. Это не принудительный перехват LAN/других VPN.
- Одно сохранённое подключение. AWG 2.x-only параметры и VLESS WS/gRPC/XHTTP не поддерживаются.
- Реальная смена Wi-Fi/LTE на ноутбуке и sleep/resume ещё не прошли аппаратную приёмку. Сохранение активных сессий не обещается.
- Собственные EXE не имеют Authenticode-подписи. Wintun 0.14.1 подписан WireGuard; .NET runtime входит в архив.

## Установка

Архив: `quic-lab-windows-0.1.0-beta.1-x64.zip`. Распаковать полностью. `SHA256SUMS.txt` проверяет архивы, `payload-sha256.json` — содержимое пакета. Контрольные суммы подтверждают целостность, не заменяют цифровую подпись издателя.

Первичная установка пока техническая: нужен действующий приватный Windows engine JSON. `engine.example.json` содержит только шаблон; его placeholders нельзя использовать как учётные данные. В обычном терминале получить SID через `whoami /user`. Затем в **Windows PowerShell x64 от администратора**, находясь в каталоге распаковки:

```powershell
./Install.ps1 -Profile C:/private/engine.json -OwnerSID S-1-5-21-...
```

После установки запустить `C:/Program Files/QUIC Lab Windows Preview/ui/QuicLab.Windows.exe` обычным пользователем. VPN изначально выключен. Последующие настройки и импорт URL доступны в GUI; закрытие окна не останавливает подключённый VPN.

Установщик использует прежнее имя службы `QuicLabWindowsPreview` и каталоги `QUIC Lab Windows Preview`. Он **отказывается перезаписывать существующую установку**. Автоматический upgrade не входит в beta. Для обновления существующей установки следует остановить VPN/службу, закрыть GUI и заменить бинарный payload с проверкой manifest, сохранив защищённый каталог ProgramData и регистрацию службы. Не удалять `settings-v1.dpapi` и не копировать его между компьютерами: DPAPI привязан к среде. На данном этапе такая миграция выполняется администратором отдельно от Install.ps1.

Удаление регистрации службы: `./Install.ps1 -Action Remove` от администратора. Бинарники и приватные данные намеренно остаются на диске.

## Проверки

Свежий прогон перед упаковкой 2026-10-14:

- `go test -count=1` для windowsengine, windowsclient, vpnclient, approuting, awg/netstack, vless, icmprelay, routing, vpnmodel — PASS.
- `go vet` Windows engine/service и windowsclient/windowsengine — PASS.
- ContractTests с protocol-v1.json, AppSelectionTests, WPF UiTests — PASS. Проверены 256 подсетей, импорт URL, сохранение/конфликт ревизий, размеры окна, счётчики, закрытие/повторное открытие.
- Release-сборка обоих Go EXE и self-contained WPF win-x64 — PASS; подпись включённого Wintun — Valid.

Полный `go test ./...` на этом Windows checkout не проходит: серверные пакеты/интеграционные тесты требуют Linux, а ignored artifacts содержат исследовательские Go-файлы. Это не заявляется как успешная полная серверная регрессия. Отдельные server-dependent gateway/mobile test suites также требуют Linux; production Windows binaries из этих исходников успешно собраны.

Ранее выполненная live-приёмка текущего кода (не повторная проверка каждого байта релизного архива): QUIC/HTTPS full IPv4, DNS TCP/UDP и системный resolver, три цикла очистки/переподключения; AWG TCP/UDP/ICMP и VLESS TLS/REALITY TCP/UDP в режиме подсетей. Подробнее: docs/testing/windows-full-ipv4.md и docs/testing/windows-settings-transports.md. Среда live-приёмки — Windows 10 x64; отдельная приёмка Windows 11 и ARM64 не заявляется.

Исходники доступны по тегу `windows-v0.1.0-beta.1` и в отдельном source-архиве. Приватные профили и журналы в дистрибутив не входят.
