# Linux client preview

Первый рабочий CLI: QUIC/HTTPS, IPv4, 1–256 выбранных подсетей. Нет GUI, AWG/VLESS, MDM, полного маршрута /0 и автоматического переключения физической сети. Системные DNS и IPv6-маршруты не меняются. Kill switch отсутствует: после остановки VPN трафик снова использует обычную маршрутизацию.

## Запуск

Нужны Linux amd64, /dev/net/tun, iproute2, root и профиль QUIC Lab с клиентским сертификатом. Скопируйте client.example.json, замените endpoint на IPv4:port сервера, hostname на TLS-имя, certificate/key/ca на PEM-строки профиля (не пути к файлам). Файл содержит секреты. Пример намеренно не содержит рабочих ключей.

```sh
chmod 600 client.json
./quic-lab-client -validate -config client.json
sudo ./quic-lab-client -config client.json
```

Ctrl+C удаляет собственный временный TUN и связанные маршруты. При обнаруженной потере транспорта клиент очищает ресурсы и завершается с кодом 1; обнаружение зависит от таймаутов транспорта. Журнал выводит состояние и счётчики. -validate проверяет структуру; сертификаты проверяются при подключении.

Клиент отклоняет перекрывающиеся подсети, захват адреса VPN-сервера, конфликты с существующими маршрутами и нестандартные policy rules. Физический интерфейс определяется по маршруту до сервера; сокеты привязываются к нему. После смены сети требуется перезапуск. TUN не получает фиксированного IPv4-адреса.

## Необязательный systemd

Установите бинарник в /usr/local/bin/quic-lab-client, приватный профиль в /etc/quic-lab/client.json (root:root, 0600), приложенный unit в /etc/systemd/system/quic-lab-client.service. После проверки профиля выполните systemctl daemon-reload и systemctl enable --now quic-lab-client. Unit перезапускает процесс при ошибке; он не установлен автоматически на тестовый хост.

## Проверка

scripts/test-linux-client.sh запускается root только на тестовом хосте: две временные network namespace, отдельные сертификаты, реальные TCP/UDP через QUIC/HTTPS, очистка TUN/маршрутов, сравнение SSH-маршрута хоста. Пользовательская сеть хоста не захватывается.
