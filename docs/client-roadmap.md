# План клиентов: Android, Windows и Linux

Актуализация 2026-11-05. Это сводка текущего кода и подтверждённых проверок; старые unchecked пункты не означают автоматически, что функции отсутствуют. Приоритет следующей разработки — desktop-паритет, особенно Windows; Android продолжает получать исправления общего ядра и физическую приёмку. Реализация, испытание на устройстве и публикация учитываются отдельно.

## Порядок следующих пакетов

1. **Общее ядро + Linux/Windows транспортный паритет — реализовано.** [План](superpowers/plans/2026-11-04-desktop-transport-parity.md): Linux AWG/VLESS, сохранение WebSocket в общем шлюзе, корректное объединение Windows AWG AllowedIPs. [Проверки и ограничение REALITY checkptr](testing/desktop-transport-parity-2026-11-04.md).
2. **Windows: per-app и горячие правила реализованы.** По [принятому дизайну](superpowers/specs/2026-10-14-windows-per-app-tun-design.md) подключены Windows TCP/UDP OwnerResolver, TUN/direct, два списка и неизвестный владелец, служба/WPF и счётчики. [Первый пакет](testing/windows-per-app-routing-2026-11-04.md), [горячие правила и жизненный цикл](testing/desktop-live-routing-2026-11-04.md). Изменение только правил сохраняет открытые потоки. В auto-режиме восстановление VPN на прежней сети сохраняет TUN/direct; смена физической сети и явное переподключение прерывают оба выхода. Дальше: физическая проверка двух приложений/Roblox и всех транспортов, измерения задержки/CPU/памяти. Полная приёмка per-app ещё не закрыта.
3. **Windows: библиотека профилей реализована; независимые выходы далее.** До 32 снимков в защищённом хранилище службы, сохранение/замена/удаление, выбор с сохранением локальных маршрутов, DNS, интерфейса и per-app. [Использование](windows-profile-library.md), [проверки](testing/windows-profile-library-2026-11-04.md). Работает один активный VPN; переключение требует reconnect, откат к снимку ручной. Далее: несколько независимых ExitID, паритет групп/подписок и библиотека Linux.
4. **Linux: per-app, горячие правила и восстановление реализованы.** Режимы `only_selected`/`all_except_selected`, case-sensitive пути, procfs TCP/UDP, VPN/direct, unknown, счётчики и systemd drop-in. [Настройка](linux-client-preview.md), [приёмка](testing/linux-per-app-routing-2026-11-04.md), [горячие правила](testing/desktop-live-routing-2026-11-04.md). Правила внутри выбранных IPv4-подсетей обновляются по SIGHUP; QUIC/HTTPS восстанавливаются с сохранением direct. AWG/VLESS получили необязательный `health_dns`: проверку DNS через VPN и восстановление после трёх ошибок, также без per-app. [Проверки](testing/linux-vpn-readiness-2026-11-04.md). Это подтверждает UDP/DNS к выбранному резолверу, не все назначения/TCP; без настройки остаётся `engine_ready`. Дальше: смена физического интерфейса, библиотека профилей и приёмка установленного systemd; Windows readiness остаётся отдельной задачей.
5. **Android и общий выпуск.** Физическая приёмка накопленных групп/MDM, затем версии и публикация соответствующих компонентов. Синтетические тесты и debug APK не закрывают физические пункты.

Полный kill switch/IPv6-изоляция — отдельное развитие с системной приёмкой. Принятый Windows per-app дизайн управляет IPv4 через TUN/direct, не обещает kernel-изоляцию выбранных приложений при аварии процесса. Linux preview также не имеет kill switch и не меняет системный DNS/IPv6.
