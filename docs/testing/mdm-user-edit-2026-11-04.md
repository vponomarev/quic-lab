# Редактирование MDM пользователем — 2026-11-04

Реализовано в ветке `codex/server-exits`, база этой задачи `c3d6be5`.
Production-сервер не обновлялся; публикации APK нет.

## Использование

1. Администратор открывает WEB-управление конкретным MDM-устройством → обзор →
   «Редактирование с телефона», включает «Разрешить пользователю менять
   MDM-настройки» и сохраняет право. По умолчанию оно выключено.
2. На телефоне: «Настройки» → «Редактировать MDM-настройки».
3. Пользователь редактирует отдельный черновик и нажимает «Отправить».
   Сервер проверяет право и версии, сохраняет ревизию и отправляет её обычным
   MDM-провижинингом. Экран различает сохранение сервером и применение телефоном.

Право относится ко всей VPN-конфигурации: профили, адреса, маршруты, приложения,
DNS, лимиты, резервные сети, диагностика и явная замена ключей. Старые ключи не
выдаются редактору. Настройки MDM-привязки, согласия, режим current/external и
административная политика выбора профилей через этот редактор не меняются.
При удалении разрешённого профиля сервер удаляет его из политики выбора.

Отзыв права, pause/смена эпохи, новая правка администратора или новая локальная
генерация блокируют устаревший запрос. Пока предыдущая ревизия не применена,
новую отправить нельзя. Повтор после потери ответа использует тот же request ID.
Конфликт не стирает черновик; явное перечитывание загружает актуальную версию.

## Принятые решения и границы

- Право выдаётся всей VPN-конфигурации конкретной MDM-привязки; отдельных ACL
  полей в этой версии нет. Если нужен более узкий доступ, потребуется новая политика.
- Редактор использует существующие общие формы, упакованные в APK. Действующие
  сложные структуры сохраняются, но новые формы авторинга автоматических групп
  в эту задачу не добавлены. Для них остаётся прежний интерфейс администратора.
- Локальные native-экраны остаются защищены MDM; отдельный черновик предотвращает
  изменение работающего VPN до ответа сервера. Цена — отдельная точка входа.
- Существующий worktree/ветка сохранены вместе с предыдущим server-exits пакетом;
  при интеграции нужно учитывать обе разработки. Push/merge/deploy не выполнялись.
- Review не подтверждает физическую приёмку Note9 и production-конфигурацию:
  первая заблокирована установкой, вторая не менялась в этой задаче.
