## Реализовано

Сохранение/замена/удаление именованных снимков в существующем атомарном DPAPI
документе; максимум 32, общий размер до 1 МиБ. Общая ревизия, клонирование
документа, сохранение библиотеки при обычных и горячих settings-изменениях.
Списки и read_settings не раскрывают ключи сохранённых профилей.

Выбор профиля сохраняет локальные маршруты/DNS/uplink/per-app; сначала проверяет
объединённые параметры, затем использует существующую транзакцию Apply.
Остановленный клиент не запускается. Running требует подтверждения reconnect.
WPF: capability gate, список, сохранение черновика, замена, выбор, удаление,
сообщения о конфликте/неизвестном результате и подтверждения.

## Независимый обзор

Один свежий read-only reviewer gpt-6-astra/high: Critical нет, два Important
исправлены в одном проходе. Повторный обзор не проводился.

- Ревизия ответа после сохранения/удаления могла уже включать изменение другого
  клиента. WPF принимал её со старым содержимым редактора и мог перезаписать
  чужие настройки. Acceptance воспроизвёл commit другого окна между сохранением
  и ответом (RED); теперь редактор принимает ровно ExpectedRevision+1 своей
  успешной операции, последующее сохранение получает revision_conflict (GREEN).
- Таймаут PipeClient вызывает OperationCanceledException, который новые действия
  библиотеки молча подавляли. Тест потери ответа после commit сначала падал;
  теперь подавляется только отмена lifetime окна, остальные отмены показывают
  неизвестный результат и необходимость перечитать настройки. Save и activation
  проверены acceptance (RED→GREEN); тот же catch filter применён к delete.

Отложенный Minor: после сохранения/удаления снимка при изменённом черновике его
baseline сохраняет старую ревизию; возврат полей к первоначальным значениям
может оставить HasChanges=true и показать лишнее подтверждение закрытия. Потери
данных нет. Полный WPF-набор после исправлений — PASS; Release UI пересобран.

## Решения и ограничения

1. Снимки в общем DPAPI-документе, библиотека после первого сохранённого
   подключения: сохраняется атомарность и прежнее поведение первого запуска.
   Цена — старая служба не читает расширенный документ при downgrade.
2. При выборе сохраняются настройки локальной маршрутизации и требуется
   reconnect работающего VPN. Цена — переключение прерывает открытые VPN/direct;
   это один активный выход, не ExitID-маршрутизация.
3. Автоматический rollback при неудачном соединении не добавлен: выбранные
   параметры остаются сохранёнными, как при обычном Apply. Цена — пользователь
   выбирает резервный снимок вручную.
4. Reviewer не оценивал физическую маршрутизацию/смену сети и сон/возобновление:
   остаётся отдельная приёмка без подмены установленного профиля. Цена — возможные
   ошибки реальной сети/OEM не исключены.
5. Upgrade и release не оценивались: сохраняются локальные артефакты. Цена —
   совместимость установленного обновления ещё не подтверждена.
6. Reviewer оставил downgrade, первое сохранённое подключение и ручной rollback
   за пределами оценки; решения 1–3 подтверждены с теми же ограничениями.
7. Несколько выходов, библиотека Linux и паритет подписок/групп не оценивались:
   это отдельные пакеты плана. Цена — здесь только один активный Windows VPN.
8. Посторонний dirty-код не оценивался и сохранён отдельно. Результаты не
   подтверждают всё объединённое незавершённое рабочее дерево.
9. Reviewer не перезапускал тесты: runtime evidence — журналы исполнителя,
   независимая проверка была по исходникам. Второго независимого запуска нет.

Физический трафик/сон/upgrade и выпуск не закрываются этим пакетом; установленные
служба, профили и сеть хоста не менялись. Библиотека Linux и паритет групп/подписок
остаются дальнейшими задачами.
