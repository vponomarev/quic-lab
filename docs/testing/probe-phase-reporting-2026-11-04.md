# Двухсетевые результаты диагностики в MDM — 2026-11-04

База `b6749a3`, ветка `codex/windows-client-beta`, существующий worktree `.worktrees/phase1-vpn`. Реализованы три связанные части: Android-передача фаз, серверная проверка/хранение, выбор сети в панели диагностики. Это продолжение согласованной архитектуры adaptive paths, не выпуск и не завершение всей физической приёмки Android.

## Поведение

- Новый сервер объявляет `vless_probe_phases_v2`; Android запоминает результат каждого sync, включая отсутствие capability после смены/понижения сервера. Новый отчёт объявляет поддержку клиента. Передача по-прежнему требует активного управления и прав VPN + telemetry.
- Сервер с новой capability получает последний допустимый локальный schema=2 snapshot: отдельные Wi-Fi/LTE phases без дублирования верхних rows. Старый сервер получает только прежний schema=1. Unknown schema исключается; совпадение source/fingerprint и ownership удалённых результатов сохраняется.
- Отчёт копирует только публичные поля с ожидаемыми скалярными типами. URL подписки, credentials, raw exceptions, ownership, произвольные поля и вложенные значения не передаются. Снимок с неверными типами пропускается без срыва основного отчёта.
- Максимум две фазы, 256 строк на фазу, снимок 768 КиБ. Снимок не добавляется, если совокупный отчёт превышает 900 КиБ; прежний транспортный предел 1 МиБ не увеличен. В таком случае результат остаётся на телефоне; автоматической разбивки на несколько запросов нет.
- Сервер сохраняет пропуски `no_network`, `permission_denied`, `budget` и фактические промежуточные/отменённые состояния. Запоздавший sequence не заменяет свежие результаты и ReceivedAt. Состав узлов между фазами должен совпадать.
- Панель позволяет выбрать Wi-Fi или LTE; выбор сохраняется при обновлении. Пропуски показаны нейтрально и входят в «Не проверены», а не «Ошибки». Отдельно показаны состояние/причина фазы и время получения результата.
- Удалённый start остаётся прежней одно-сетевой командой. Старые retry/cancel не адресуют локальные schema=2 запуски: запрет действует в панели, QueueProbe и Android, включая ещё не сообщённый серверу локальный результат. Локальная отмена через приложение сохраняется.

## Независимое ревью

Свежий рецензент проверил только изменения этой итерации. Два Important/P2 приняты и исправлены одним проходом:

1. Ограничение retry/cancel было только в UI. Native тест подтвердил приём обеих команд, Android-тест — отсутствие запрета cancel. Добавлены серверная проверка сохранённого schema и Android-проверка локального хранилища до обращения к coordinator.
2. Копирование значения разрешённого поля допускало JSONObject/JSONArray, например вложенный секрет внутри name. Тест подтвердил передачу такого объекта. Проектор теперь проверяет ожидаемый String/целочисленный тип и исключает неверный снимок.

RED: `review-red-native.log`; Android 10 тестов, два ожидаемых падения — `review-red-device.log`. Повторное ревью не проводилось; исправления проверяются воспроизведениями и общей регрессией.

## Решения и оставшиеся границы

- Применена расширяемая схема существующего ProbeSnapshot вместо нового endpoint/хранилища или потери одной фазы при преобразовании в v1. Новая capability не расширяет разрешения на запуск.
- Агрегированный источник «Все VLESS-источники» (`__all_vless_sources__`) по-прежнему исключается текущим списком источников MDM. Это прежнее ограничение, отдельная последующая задача; обычные сообщаемые источники получают обе фазы.
- Физические LTE, Doze/OEM и аккумулятор этой итерацией не измерялись; результаты синтетических тестов не являются такой приёмкой. Удалённая оркестрация двух фаз остаётся отдельным расширением.
- Все замечания Important исправлены. Более широкое ужесточение семантики повреждённых локальных данных вне явной границы публичного проектора не добавлялось без установленного сценария; сервер сохраняет собственную валидацию.
- Рецензент не запускал Go/ADB. Основной исполнитель запускал проверки на разрешённом изолированном Linux-хосте и Note9. Серверные изменения не развёрнуты, ветка не опубликована; посторонние незавершённые cell/admin/server изменения сохранены вне коммита. Go mobile/AAR не менялся: изменения Go относятся к серверному MDM.
