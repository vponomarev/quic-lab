# Desktop: горячие правила и восстановление VPN — 2026-11-04

Изменения поверх d414279, ветка `codex/windows-client-beta`, worktree
`.worktrees/phase1-vpn`. [План](../superpowers/plans/2026-11-04-desktop-live-routing.md),
[спецификация](../superpowers/specs/2026-11-04-desktop-live-routing.md).

## Поведение

- Общий DesktopAppRouter атомарно публикует правила для новых потоков. Уже
  выбранные TCP/UDP-потоки сохраняют выход, включая выключение per-app.
  Включение per-app также не пересоздаёт TUN.
- VPN-поколение отделено от TUN/direct. При обнаруженном сбое VPN-потоки
  закрываются, VPN/DNS недоступны до восстановления; перехода в direct нет.
  Счётчики VPN суммируются между поколениями.
- Windows: изменение только `app_routing` сначала сохраняется службой, затем
  публикуется без Stop. Ошибка сохранения оставляет прежнюю политику/ревизию.
  Возможность `app-routing-live-v1` включает этот путь в WPF; старые службы
  сохраняют подтверждение переподключения. Другие настройки требуют прежнего
  переподключения. Automatic сохраняет последнюю политику для будущих engines.
- Windows: восстановление без потери direct работает через Automatic при
  **автоматическом выборе интерфейса**. Ручной выбор интерфейса сохраняет прежний
  режим без автоматического supervisor; горячие правила работают и в нём.
- Linux: SIGHUP заново открывает приватный профиль, принимает только app-политику.
  Невалидные и прочие изменения отклоняются. Для сеанса, в котором включалась
  per-app, повторные подключения ограничены 25 секундами на попытку, backoff
  3–30 секунд. Stop отменяет попытку. Обычный запуск без per-app сохраняет
  прежнее завершение при обнаруженной потере VPN.

## Границы и принятые решения

1. Сохраняем direct только при восстановлении на той же физической сети.
   Смена uplink делает привязанные сокеты непригодными: оба выхода пересоздаются.
   Цена неверного ожидания — обрыв активных direct-соединений при смене сети.
2. AWG/VLESS сохраняют семантику локального `engine_ready`. Проверяемая удалённая
   готовность остаётся отдельной задачей; тихая потеря сервера может не запустить
   восстановление. Их live-матрица проверяет горячие правила, не outage/recovery.
3. Ручной Windows uplink не переводится автоматически в Automatic: существующие
   конфигурации подсетей могут не иметь default route, нужного обнаружению.
   Цена — в ручном режиме потеря VPN пока требует явного переподключения.
4. POSIX task-helper команды заменены явными запусками на Linux и нативными
   тестовыми бинарниками на Windows, с ручной записью результатов. Цена —
   менее автоматизированный учёт; журналы сохранены для проверки.
5. Reviewer отдельно оставил за пределами оценки AWG/VLESS remote readiness,
   manual Windows recovery и сохранение direct при смене uplink. Подтверждены
   решения 1–3 с теми же ограничениями, они не считаются завершённой приёмкой.
6. За пределами оценки IPv6-изоляция, kill switch и расширенное управление DNS:
   прежняя область захвата сохраняется. Цена — трафик вне захвата и после Stop
   может использовать обычные системные маршруты.
7. За пределами оценки физический Windows/Roblox/нагрузка, REALITY outage и
   установленный systemd. Они остаются явными задачами приёмки; цена — возможные
   ошибки конкретных платформ/провайдеров до этих испытаний.
8. Посторонние dirty-файлы не оценивались и не включены в коммит/тестовую копию.
   Цена — результаты не подтверждают весь объединённый незавершённый worktree.

Не выполнены физическая Windows per-app/recovery приёмка, Roblox/нагрузка,
REALITY outage, systemd установленной службы, физическая смена сети и выпуск.
Установленные службы/профили не заменялись. Kill switch и IPv6-изоляция не добавлены.
