12.10.2026. Реализация доступна в тестовом контуре. Production/release gate ещё не закрыт; ниже добавлена внешняя приёмка кандидата 0.9.4-pre.3.

## Среда

- Изолированный VPN/echo на 192.168.5.214. Production не изменён.

## Проверено

- 7 instrumentation-проверок default deny, отдельного согласия, отзыва, сохранения списка и объединения охвата Android TUN.
- Физическая матрица QUIC/HTTPS × vpn_only/vpn_plus_apps/all_apps: TCP, UDP, открытый DNS, отзыв согласия без изменения соединения. Вместе с матрицей OK (8 tests), 147.691s.
- На echo-порту прямой трафик приходит с 192.168.5.200, VPN с адреса сервера 192.168.5.214. Проверялись заголовки/размеры, без сохранения содержимого пакетов.
- В хранилище стенда присутствуют client/direct, включая DNS прямого приложения; server/direct отсутствует.
- Linux targeted race tests Research/Multiple, research storage, routing, MDM права/совместимость и WEB query прошли.
- Полная mobile race regression прошла за 54.773s. При параллельной сборке несколько раз получен таймаут существующего TestBothPathsTemporarilyUnavailable. Изолированно count=3 прошёл; неизменённая база прошла три полных запуска. Причина нестабильности не доказана; не скрывать при выпуске.

## Повторная проверка после ревью

- Итоговая Linux race regression: mobile 53.924s, routing/research, gateway 1.155s, mdm 1.801s, admin 17.726s — PASS. Сервер собирается на Linux; APK/AAR собираются.
- Note9: ResearchScopeTest + ResearchConsentTest + MdmApplyCoordinatorTest — 12/12; восстановление сохранённой researchScope до подтверждения ревизии проверено.
- Минутные окна QUIC/HTTPS: отдельный физический прогон PASS (172.891s). Восемь потоков TCP/UDP совпали с echo по байтам вверх и вниз: QUIC VPN TCP 57/57, UDP 61/61, direct TCP 60/60, UDP 64/64; HTTPS VPN TCP 58/58, UDP 62/62, direct TCP 61/61, UDP 65/65. server/direct отсутствует.
- После исправления атрибуции по захваченному UID: 13/13, включая минутный QUIC/direct прогон (94.091s). Последняя UDP-дельта direct: 64/64 байта, known, ru.vpnc.quicprobe.direct.
- WEB: фильтры client/direct и JSONL проверены браузером, 62 записи с корректным маршрутом плюс служебные строки. Desktop 1440px и узкий экран 390px без горизонтального переполнения страницы; таблица прокручивается отдельно.
- Ревью: исправлены потеря отзыва при подписке, проверка прав известных MDM-регистраций на сервере, восстановление researchScope перед ACK, сохранение ограниченной direct-очереди при отзыве. Historical-пакет не разрешает новые наблюдения; отказанный сервером grant не даёт права на historical.
- Дополнительно: позднее уточнение выхода не теряет счётчики; неизменившийся scope не сбрасывает сборщик; lookup UID короткого direct-потока сохраняется для асинхронного имени приложения.

## Итоговая проверка совместимости и MDM

- На последнем APK Note9 прошли 19/19 проверок (10.714s): scope/consent, применение и восстановление MDM, отчёт, UID lookup. Экран охвата дополнительно проверен по снимку: согласие выключено, несовместимый текущий AWG объяснён, права не изменились.
- Реальный HTTPS MDM на отдельной тестовой привязке: enrollment → capability/права → report → desired all_apps → применение → report/ACK → удаление тестовой привязки: 1/1, 7.441s. Рабочая привязка телефона не заменялась.
- Отдельно браузером проверено создание desired all_apps через WEB-редактор. Этот WEB-тест и Android HTTPS-тест используют разные тестовые привязки; единый сценарий клика и применения на одной привязке пока не прогонялся.
- Новый клиент согласует research_scope_v1 с сервером: дополнительные права и поля отчёта не отправляются старому серверу до согласования. Идентификаторы VPN-регистраций передаются только при праве конфигурации или исследования; сервер сохраняет известную связь при последующем отзыве права.
- Повторная Linux race regression шести пакетов PASS (кэш для неизменённых пакетов). После установки и тестов на Note9 подтверждены активные рабочие VPN и MDM.

## Внешняя приёмка 0.9.4-pre.3 (Note9)

Старый сервер 87.228.55.179 использован как отдельный стенд: новые ключи/данные и порты 18453/UDP, 18454/TCP, 18456/TCP+UDP, MDM 19465/TCP. Сервисы прежнего VPN не запускались, 3x-ui не изменён. Рабочий quic-lab.vpnc.ru не обновлялся.

- LTE: QUIC/HTTPS × vpn_only/vpn_plus_apps/all_apps, TCP/UDP, открытый DNS, отзыв — PASS, 150.574s.
- QUIC/HTTPS, all_apps: по четыре переключения Wi-Fi/LTE на транспорт, TCP/UDP для VPN и direct после каждого переключения — PASS, 350.161s.
- Один сквозной WEB → MDM → Note9 → report/ACK через LTE: браузер задаёт all_apps, телефон применяет, VPN-список сохраняется — PASS, 9.830s.
- Сетевые заголовки echo подтверждают разные источники VPN/direct. В серверных записях нет server/direct. Часть VPN-UDP потоков, завершённых отзывом/перезапуском до минутной выгрузки, содержит только flow_open: это не полный счётчик трафика. Direct и серверные наблюдения не суммируются с VPN-клиентскими.
- Тестовая обвязка скорректирована: после UiAutomation обновляется package Context Android 11; ожидание видимости Activity не используется для работы при заблокированном экране. Android останавливает процесс после instrumentation; фоновый прогон запускается обычным launcher intent уже вне instrumentation.
- Полная Linux-регрессия cmd/internal/mobile с race — PASS с прежним точечным исключением checkptr для Xray outbound/inbound. Без исключения тот же upstream fatal воспроизведён и на исходной базе 71188b9; продуктовые флаги сборки не менялись. См. [обоснование исключения](../release-v0.8.0-regression.md#racecheckptr-qualification).
- Сравнительный фон вне instrumentation, экран выключен: vpn_only 5 минут + all_apps 20 минут — PASS, 596 успешных операций TCP/UDP. В all_apps оба приложения захвачены TUN, но выходы VPN/direct различаются. Один PID сохранялся все 20 минут.
- PSS: vpn_only 58 941–62 728 КиБ, all_apps 59 381–72 902 КиБ; дескрипторы 89 в базовом режиме, 99–137 в all_apps, в конце 99. Это короткий smoke/soak, не гарантия отсутствия длительной утечки или оценка батареи.
- Медиана TCP/UDP, мс: vpn_only VPN 64/41,5, direct 50,5/23; all_apps VPN 63/49, direct 66/32. Последовательные WAN-замеры, поэтому разницу нельзя целиком приписывать накладным расходам анализа.
- Штатный `adb shell am crash`: PID сменился за 2,38 с; спустя 15 с после обнаружения нового PID оба приложения успешно передают TCP через прежние VPN/direct маршруты. Это имитация аварии процесса, не force-stop/перезагрузка/полный тест OEM-очистки.
- DROP только тестовых VPN-портов: VPN-приложение получает таймаут, direct продолжает передавать; после удаления правил оба работают. Установлен страховочный таймер снятия правил; по окончании правил нет. Это проверка отсутствия fallback на direct при отказе VPN, не тест всех сетевых отказов.
- Перехваченный direct IPv6: ожидаемый NoRouteToHost, обхода TUN нет.
- Финальная pre.3 Android-регрессия: 18/18, 17,885 с. Повторный визуальный UI-тест не выполнялся из-за блокировки экрана; прежняя визуальная проверка относится к тому же продуктовому коду, до изменения номера версии.
- Завершение тестов: исходные профиль/права/охват Note9 восстановлены, MDM работает. Автоматический старт исходного VPN из instrumentation не прошёл: журнал подтверждает `Package android does not belong to 10079` (контекст UiAutomation Android 11). Сам VPN после очистки тестового контура выключен. Исправленная тестовая процедура подготовки запуска с обычного launcher собирается, но повторную установку test APK телефон отклонил `INSTALL_FAILED_USER_RESTRICTED`; эта процедура пока не проверена. Ошибка cleanup означает, что весь orchestrator не считается полностью зелёным, несмотря на успешные аварийные сетевые assertions.

Кандидат: **0.9.4-pre.3 (59)**, SHA-256 `2debc12dcdd6d5930e5e1933110542af44b6fa5b3d4847082fce93b69a07646d`. APK сохранён локально в игнорируемом `artifacts/releases/research-scope-pre3/`. Нового production-релиза нет. Подготовка отдельного тестового доступа Note12 (переключение временных служб и экспорт тестовых credentials) остановлена автоматической проверкой до отдельного разрешения пользователя. Поэтому для расширенного анализа на Note12 нужен ещё тестовый профиль/доступ; установка APK сама по себе не обновляет production server.

## Особенности

Системный резолвер может скрывать исходное приложение; такие запросы остаются с неизвестным владельцем и следуют явной общей DNS-политике. Для app-owned direct DNS выбран прямой выход. IPv6 в перехваченном трафике блокируется, как и ранее; при расширении охвата это затрагивает дополнительные приложения и обозначено в UI.
