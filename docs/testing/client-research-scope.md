# Проверка охвата клиентского исследования

12.10.2026. Реализация доступна в тестовом контуре. Production/release gate ещё не закрыт.

## Среда

- Note9, ADB dc69eb2c; два контрольных приложения ru.vpnc.quicprobe и ru.vpnc.quicprobe.direct.
- Изолированный VPN/echo на 192.168.5.214. Production не изменён.
- Go/race и gomobile AAR на Linux; Android Gradle/JDK17 на Windows.

## Проверено

- 7 instrumentation-проверок default deny, отдельного согласия, отзыва, сохранения списка и объединения охвата Android TUN.
- Физическая матрица QUIC/HTTPS × vpn_only/vpn_plus_apps/all_apps: TCP, UDP, открытый DNS, отзыв согласия без изменения соединения. Вместе с матрицей OK (8 tests), 147.691s.
- На echo-порту прямой трафик приходит с 192.168.5.200, VPN с адреса сервера 192.168.5.214. Проверялись заголовки/размеры, без сохранения содержимого пакетов.
- В хранилище стенда присутствуют client/direct, включая DNS прямого приложения; server/direct отсутствует.
- Linux targeted race tests Research/Multiple, research storage, routing, MDM права/совместимость и WEB query прошли.
- Полная mobile race regression прошла за 54.773s. При параллельной сборке несколько раз получен таймаут существующего TestBothPathsTemporarilyUnavailable. Изолированно count=3 прошёл; неизменённая база прошла три полных запуска. Причина нестабильности не доказана; не скрывать при выпуске.

## Повторная проверка после ревью

- Итоговая Linux race regression: mobile 53.924s, routing/research, gateway 1.155s, mdm 1.801s, admin 17.726s — PASS. Сервер собирается на Linux; APK/AAR собираются.
- Note9: ResearchScopeTest + ResearchConsentTest + MdmApplyCoordinatorTest — 12/12; восстановление сохранённой researchScope до подтверждения ревизии проверено.
- Минутные окна QUIC/HTTPS: отдельный физический прогон PASS (172.891s). Восемь потоков TCP/UDP совпали с echo по байтам вверх и вниз: QUIC VPN TCP 57/57, UDP 61/61, direct TCP 60/60, UDP 64/64; HTTPS VPN TCP 58/58, UDP 62/62, direct TCP 61/61, UDP 65/65. server/direct отсутствует.
- После исправления атрибуции по захваченному UID: 13/13, включая минутный QUIC/direct прогон (94.091s). Последняя UDP-дельта direct: 64/64 байта, known, ru.vpnc.quicprobe.direct.
- WEB: фильтры client/direct и JSONL проверены браузером, 62 записи с корректным маршрутом плюс служебные строки. Desktop 1440px и узкий экран 390px без горизонтального переполнения страницы; таблица прокручивается отдельно.
- Ревью: исправлены потеря отзыва при подписке, проверка прав известных MDM-регистраций на сервере, восстановление researchScope перед ACK, сохранение ограниченной direct-очереди при отзыве. Historical-пакет не разрешает новые наблюдения; отказанный сервером grant не даёт права на historical.
- Дополнительно: позднее уточнение выхода не теряет счётчики; неизменившийся scope не сбрасывает сборщик; lookup UID короткого direct-потока сохраняется для асинхронного имени приложения.

## Итоговая проверка совместимости и MDM

- На последнем APK Note9 прошли 19/19 проверок (10.714s): scope/consent, применение и восстановление MDM, отчёт, UID lookup. Экран охвата дополнительно проверен по снимку: согласие выключено, несовместимый текущий AWG объяснён, права не изменились.
- Реальный HTTPS MDM на отдельной тестовой привязке: enrollment → capability/права → report → desired all_apps → применение → report/ACK → удаление тестовой привязки: 1/1, 7.441s. Рабочая привязка телефона не заменялась.
- Отдельно браузером проверено создание desired all_apps через WEB-редактор. Этот WEB-тест и Android HTTPS-тест используют разные тестовые привязки; единый сценарий клика и применения на одной привязке пока не прогонялся.
- Новый клиент согласует research_scope_v1 с сервером: дополнительные права и поля отчёта не отправляются старому серверу до согласования. Идентификаторы VPN-регистраций передаются только при праве конфигурации или исследования; сервер сохраняет известную связь при последующем отзыве права.
- Повторная Linux race regression шести пакетов PASS (кэш для неизменённых пакетов). После установки и тестов на Note9 подтверждены активные рабочие VPN и MDM.

## До выпуска

- Физический Wi-Fi/LTE с внешним **тестовым** VPN/echo. Этот стенд доступен по LAN 192.168.5.214; успешный Wi-Fi-прогон не доказывает LTE. На production эксперименты маршрутизации не проводились.
- Единый сценарий WEB MDM → телефон → report на одной тестовой привязке. Сетевой HTTPS-путь на телефоне и отправка из WEB уже проверены отдельно, как описано выше.
- Сравнительные замеры задержки/памяти длительного расширенного сбора и физическая гибель процесса в новом режиме. Очереди, конкуренция, отказ политики/сервера и маршрутизация проверены автоматическими тестами.
- Совместный выпуск APK/сервера с резервной копией и откатом. Релиз и версия в магазине обновлений этой итерацией не публиковались.

## Особенности

Системный резолвер может скрывать исходное приложение; такие запросы остаются с неизвестным владельцем и следуют явной общей DNS-политике. Для app-owned direct DNS выбран прямой выход. IPv6 в перехваченном трафике блокируется, как и ранее; при расширении охвата это затрагивает дополнительные приложения и обозначено в UI.
