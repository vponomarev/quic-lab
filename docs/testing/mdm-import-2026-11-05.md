# Импорт в MDM-редактор телефона — 2026-11-05

Ветка `codex/server-exits`, база пакета `0732e0b`. Дополнение к
[редактированию MDM с телефона](mdm-user-edit-2026-11-04.md).

## Использование

Администратор разрешает редактирование для устройства. На телефоне открыть
«Настройки → Редактировать MDM-настройки → Импортировать из файла».
Поддерживаются переносимые пакеты `quic-lab-config`: JSON без ключей и
зашифрованные `.age` с ключами. Для `.age` пароль вводится в native-диалоге.

Режимы: добавить подключения, обновить выбранные подключения, заменить весь
конфиг. При обновлении пользователь сопоставляет исходные профили с профилями
черновика; внешние ссылки также требуют сопоставления. Добавленные профили
получают новые идентификаторы. Импорт меняет только черновик. Пользователь
проверяет его и отдельно нажимает «Отправить»; сервер сохраняет ревизию и
провижнит её на телефон обычным MDM-циклом.

Предел входного файла — 2 МиБ, результата — 1 МиБ. Административная политика
выбора профилей сохраняется; сервер удаляет из неё удалённые профили. Права MDM
импортом не выдаются. Старые ключи сервер не возвращает; новые скрыты в preview.
Отмена сохраняет исходный черновик, собственные буферы файла очищаются, ссылки
на расшифрованные данные освобождаются. Это не обещание полного стирания
immutable строк JVM/Go из памяти.

## Подтверждённые проверки

- Linux: `go test ./... -count=1`, `go vet ./...`, race для `internal/mdm`,
  `internal/configtransfer`, `internal/admin` — PASS.
- Node: импорт не отправляет конфиг автоматически, сохраняет CAS/policy
  baseline, отмена сохраняет черновик; прежние probe-формы — PASS.
- Android: debug APK, instrumentation APK, JVM 2/2, lint — PASS.
- Note9 `dc69eb2c`, Android 11: редактор, helper и native-flow импорта, WebView
  и тихий MDM — **28/28 PASS**, 28.479 s, без пропусков. Включены отмена picker,
  пароля/сопоставления, pause до/после worker, close перед доставкой результата,
  неизменность runtime/черновика, очистка ссылок и буфера, защита окна пароля.
- Реальный HTTPS: Note9 → отдельный Linux-стенд `192.168.5.214:19447` →
  сохранение → polling → применение → report/ack — **1/1 PASS**, 19.53 s.
  Проверены grant, encrypted import, отсутствие локального применения до
  provisioning, идемпотентный повтор, скрытие ключей и отказ записи после revoke.
  Серверный fixture завершился успешно за 55.36 s.

HTTPS fixture использует production `Store`, `NewHandler`, `MdmTransport` и
координатор применения. Хранилище и Android-контекст изолированы, сертификат и
учётные данные одноразовые; VPN-порт в тесте неактивен, ключи синтетические.
Тест не подтверждает передачу VPN-трафика с импортированным провайдером.
Fixture включается только переменными `MDM_FIXTURE_ENDPOINT`/`MDM_FIXTURE_INFO`,
Android-тест — instrumentation arguments `mdm_endpoint/token/ca/admin`.
Без параметров этот интеграционный тест пропускается. Production endpoints
для управления fixture не добавлены; сервер стенда автоматически закрыт.

## Review и границы

Один независимый read-only review: Critical нет, Important — отсутствие прямых
тестов отмены и lifecycle нового native-координатора. Добавлены тесты реального
`MdmUserImportFlow` с управляемым executor, native-диалогами и ContentResolver;
пустая Activity/provider существуют только в debug source set. Provider не
экспортируется; Activity запускается через shell и защищена системным правом DUMP.

Проверка дополнительно обнаружила отсутствие `FLAG_SECURE` у окна пароля,
несмотря на защищённое окно родительской Activity. Добавлен явный флаг,
instrumentation подтвердил RED до исправления и GREEN после. Первые прогоны
тестового host были заблокированы MIUI до запуска Activity; запуск через shell
с ограниченным ожиданием устранил эту проблему окружения. Проверки отмены
ожидают асинхронные callbacks кнопок Android перед проверкой результата.

Сырые AWG-файлы/VLESS-URL не являются переносимыми пакетами этого импортера;
для них остаются явные поля ключей. Новая форма создания автоматических групп
не добавлена. Проверки других Android/OEM и document providers, поворот экрана,
длительный Doze и физический VPN-сеанс остаются приёмкой перед выпуском.
