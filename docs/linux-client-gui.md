# Linux GUI preview: управление подключением

Первый этап — окно на Go/Fyne для уже настроенной службы. Редактора и
импорта профилей пока нет. Выбор QUIC/HTTPS/AmneziaWG/VLESS, подключение,
отключение, переподключение, автозапуск VPN при загрузке, RTT, трафик/скорость и
очищенные события доступны без терминала после установки администратором.
Закрытие окна оставляет VPN работающим. Переключение активного профиля требует
подтверждения и разрывает соединения; kill switch отсутствует.

## Установка поверх настроенного Linux-клиента

Требуется Linux с systemd/journalctl и графическим сеансом X11/XWayland.
Python, PyGObject и GTK для работы клиента не нужны. Один исполняемый файл
содержит GUI, VPN-движок, локальный контроллер и установщик. Это динамический
ELF: системные библиотеки glibc, OpenGL и X11 остаются необходимы.

Установка готового бинарника поверх настроенного клиента:

```sh
chmod +x ./quic-lab
sudo ./quic-lab install --user "$USER"
```

После установки откройте **QUIC Lab** в меню приложений или выполните
`quic-lab` / `quic-lab-gui` без sudo. GUI не нужно запускать с правами root.
При обновлении сначала закройте старое окно: VPN продолжит работать.
Установщик перезапускает работающий VPN; соединения кратковременно прерываются.
Если VPN был выключен, он остаётся выключенным.

Уже должны существовать:

- `/usr/local/bin/quic-lab-client` и `quic-lab-client.service`, чей эффективный
  ExecStart равен `/usr/local/bin/quic-lab-client -config /etc/quic-lab/client.json`;
- `/etc/quic-lab/profiles/quic.json`, `https.json`, `awg.json`, `vless.json` —
  приватные root-owned 0600 файлы; отсутствующий/небезопасный профиль не показан;
- `/etc/quic-lab/client.json` — ссылка на один из этих профилей. Ручной профиль
  вне списка не заменяется через GUI, но работающую службу можно остановить.

Установщик устанавливает `/usr/local/bin/quic-lab` и совместимые ссылки
`quic-lab-client` / `quic-lab-gui` на этот же файл, обновляет контроллер и ярлык.
VPN unit, сетевые настройки, профили, выбранный профиль и политика автозапуска
сохраняются. Распознанный старый Python helper DNS/IPv6 заменяется ссылкой на тот же Go-бинарник; его поведение сохраняется. Неизвестный helper установщик не заменяет.
Доступ к управлению разрешается одному Linux UID, указанному
через имя пользователя. При ошибке запуска установка автоматически откатывается.
Резервные копии изменённых файлов и `manifest.json` находятся в
`/var/backups/quic-lab-client/*-go-gui-*`; каталог доступен только root.

Обновление — повторный запуск `sudo ./quic-lab install --user "$USER"`.
Старые системные Python/GTK пакеты не удаляются: они могут быть нужны другим
приложениям. Исходники прежнего Python GUI больше не входят в текущую поставку.

## Сборка

На Linux с Go версии из `go.mod`, C-компилятором и графическими заголовками:

```sh
sudo apt install build-essential pkg-config libgl1-mesa-dev xorg-dev libxkbcommon-dev libegl1-mesa-dev libwayland-dev
bash scripts/build-linux-gui.sh artifacts/quic-lab
```

Собирайте на самой старой поддерживаемой glibc-системе. Для переноса готового
бинарника проверяйте `ldd ./quic-lab` на целевой машине. Отдельная CLI-сборка
`go build ./cmd/linux-vpn-client` не импортирует Fyne и остаётся доступна.

## Как пользоваться

1. Откройте QUIC Lab. Главный экран покажет текущий профиль и состояние службы.
2. Выберите готовое подключение и нажмите **Подключить**. Если VPN работает,
   кнопка **Переключить** запросит подтверждение.
3. **Отключить** останавливает VPN; **Переподключить** перезапускает текущий профиль.
4. Флажок автозапуска управляет VPN при загрузке компьютера, а не появлением окна.
5. Счётчики относятся к текущему запуску службы. Скорость оценивается по их
   изменению между опросами; после переподключения измерение начинается заново.

Статус и RTT используют те же проверки, что Android: echo внутри QUIC/HTTPS,
ICMP через AWG, HTTPS через VLESS. «VPN подключён» означает свежий ответ
транспорта; это не гарантия доступности любого сайта. Для VLESS RTT включает
HTTPS-запрос, поэтому его нельзя напрямую сравнивать с echo RTT других протоколов.
Проверки выполняются раз в секунду, для VLESS — не чаще раза в пять секунд.
Если ответ старше 5 секунд (15 для VLESS), RTT заменяется на «—» и статус
сообщает об отсутствии свежих ответов. При переподключении старый RTT очищается
сразу. Фоновое обновление не блокирует кнопки и флажок автозапуска.

Отдельно показываются успешная DNS-проверка через VPN, её ошибка и восстановление
соединения. Если DNS-проверка не настроена, окно прямо указывает, что она не
подтверждена. Если control service недоступен, окно сообщает,
что состояние VPN неизвестно, вместо ложного сообщения об отключении.
События показывают только известные категории, без ключей и сырых ошибок.
Полный административный журнал: `sudo journalctl -u quic-lab-client -n 60`.

## Локальный доступ и ограничения

Окно общается только через `/run/quic-lab-control/control.sock`, TCP-порт не
открывается. Сервер проверяет UID клиента по SO_PEERCRED, GUI проверяет root UID
сервера. Ключи остаются в закрытых root-файлах. Другие процессы разрешённого
пользователя также могут управлять его VPN. Произвольные команды, пути, имена
служб и конфигурации через API не принимаются.

Нет tray, редактора маршрутов/DNS, импорта, выбора server exit и MDM. Эти функции
не входят в первый этап. Конфигурация сетевого захвата остаётся той, что хранится
в выбранных готовых профилях. Если unit переопределён на другой executable или
config path, управление отклоняется. Совместимость иных дистрибутивов и
графических окружений требует отдельной приёмки.

Удаление только GUI (VPN продолжает работать):

```sh
sudo bash packaging/linux/uninstall-gui.sh
```
