# Управляемый VLESS-сервер (V2)

VLESS — отдельный Linux/systemd worker на закреплённом Xray-core v1.260327.0. Поддерживаются TCP/RAW + TLS и REALITY, включая Vision. Установка — штатным install-server.py с --enable-vless; параметры и восстановление описаны в [инструкции установки](install-server.md).

## Использование

1. Включите отдельный VLESS listener при установке. Его TCP-порт должен быть свободен и доступен клиентам.
2. В админке откройте «VLESS-сервер», настройте TLS либо REALITY и дождитесь подтверждения применения ревизии. Изменение параметров входа может разорвать текущие подключения.
3. Разрешите VLESS пользователю. QR QUIC Lab регистрирует отдельное устройство при каждом новом импорте; каждое устройство получает отдельный случайный VLESS UUID.
4. QR VLESS устройства содержит один URI и существующий секрет доступа этого устройства. Повторное сканирование этого QR использует тот же доступ. Его можно импортировать в совместимый сторонний клиент.
5. QUIC Lab получает VLESS и через обновление управляемого профиля. Для этого нужен Android code26 или новее. Конфигурация хранится в encrypted identity. В V2 транспорт выбирается вручную; общий demux/fallback через VLESS относится к V3.

По умолчанию одновременно допускаются 15 устройств. device_limit в admin.json настраивается от1 до512; вместимость не ниже30 сохранена по уточнению владельца. Несколько TCP/UDP-соединений одного устройства и его QUIC/HTTPS/AWG/VLESS используют один общий admission. Технический предел записей VLESS, включая отключённые, —512; превышение отклоняется до сохранения, существующие устройства продолжают работать. Это не подтверждение производительности при512 активных устройствах.

## Отзыв и состояние

Отключение устройства запрещает выдачу профиля и новые подключения, закрывает все его действующие VLESS-потоки и зарегистрированные demux-сессии. Соседние устройства не отключаются. Повторное включение пользователя выдаёт новый UUID: ранее отозванный не возвращается в оборот; клиенту требуется обновить профиль.

Backend сохраняет желаемую ревизию перед её передачей worker. Успех выдаётся только после подтверждения применения. Worker хранит запреты в vless-state.json; восстановление старой копии идентичностей или tombstones недопустимо. При потере backend действующие admission leases истекают максимум за2с. После рестарта worker нужны свежий Apply и текущий admission; файл состояния сам по себе не запускает listener. Ошибка сохранения закрывает runtime до перезапуска.

Установщик проверяет применённую ревизию через приватный control socket, запуская read-only CLI от того же DynamicUser в отдельном systemd окружении. Простого состояния active недостаточно. Неудачный запуск новой версии сохраняет текущие идентичности и tombstones; постоянный recovery gate запрещает автоматический запуск восстановленных бинарников до проверки администратором.

IPC работает через Unix sockets0600 в каталоге0700. TCP API управления и публичного SOCKS нет. Служебный пользователь общий с backend; systemd StateDirectory alias разрешён только к закрытому каталогу текущего владельца.

## Demux-only и совместимость

Demux-only разрешает только указанное TCP-назначение. Домен назначения разрешается в IPv4 и сохраняется в приватном состоянии вместе с конфигурацией; рестарт и повтор той же ревизии не меняют разрешённый адрес. При сохранении того же endpoint pin остаётся прежним. Для смены назначения администратор меняет endpoint.

Нативный Xray mux не разрешён. UDP/XUDP поддерживаются, но GlobalID нормализуется в0, чтобы глобальный upstream-кэш не переносил ассоциации между устройствами и не обходил отзыв. Поэтому UDP-ассоциация не восстанавливается между внешними соединениями. Сохраняются ограничения V1: IPv4, UDP payload до8190 байт и upstream-ограничение Vision на UDP/443. Подробнее — [матрица совместимости](vless-compatibility.md).

- Linux: полный go test ./..., go vet ./..., targeted race; отдельный worker-процесс, revoke, потеря admission, SIGTERM. Проверены512 записей, общий admission, отказ переполнения до сохранения, фиксация DNS после рестарта.
- Android11 Redmi Note9Pro:37 тестов импорта/обновления/профилей; полная AAR/APK-сборка и lint без ошибок. Для TLS и REALITY/Vision на изолированном quic-demo — HTTPS и UDP DNS по Wi-Fi, LTE и после возврата Wi-Fi.
- Независимый неизменённый Xray CLI: HTTPS и SOCKS UDP через оба входа.
- По5 одновременных соединений одного UUID на каждом входе: отзыв закрыл все10, по одному соединению другого устройства остались рабочими. После рестарта отозванные UUID не принимаются. Одна немедленная проба REALITY после рестарта получила таймаут; повтор прошёл, мгновенная готовность при старте не заявляется.
- Реальный systemd257 на тестовом Linux: DynamicUser, закрытый StateDirectory alias и подтверждение ревизии между двумя служебными процессами.
- Ограничение проверки: upstream Vision использует unsafe-арифметику, несовместимую с checkptr. Полный race выполнен с отключением checkptr только для upstream VLESS; остальные пакеты сохраняют checkptr. Без этого исключения проверена матрица без REALITY/Vision.
- QR генерация и импорт проверены программно; оптическое сканирование камерой живого серверного QR в этой приёмке не повторялось.
- Нагрузочный прогон512 устройств и целевых100Мбит/с в этой приёмке не выполнялся. Старый LTE-сбой внешнего профиля pre.5 остаётся отдельным.
- Временные публичные listener и ключи удалены; на телефон возвращён pre.5. Публикация релиза и обновление рабочего сервера — отдельный checkpoint.
