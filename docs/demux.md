# Отдельный сервер объединения (экспериментальный)

Общее ядро то же, что во встроенном gateway. Внешние промежуточные VPN не завершают пользовательские TCP/UDP-потоки: конечные подключения создаёт этот сервер.

Сборка:

```sh
go build -o quic-lab-demux ./cmd/demux
./quic-lab-demux -config /etc/quic-lab/demux.json
```

Пример конфигурации (все пути и адреса — placeholders):

```json
{
  "listen": "0.0.0.0:443",
  "cert": "/etc/quic-lab/tls/fullchain.pem",
  "key": "/etc/quic-lab/tls/privkey.pem",
  "client_ca": "/etc/quic-lab/client-ca.pem",
  "allow": "0.0.0.0/0"
}
```

Слушает **UDP**, поэтому может сосуществовать с HTTPS на TCP/443; другой UDP/443 listener на этом адресе мешает запуску. Встроенный вариант использует существующий QUIC mTLS порт QUIC Lab, новые порты не нужны.
Используйте отдельный доверенный CA клиентских сертификатов. Самостоятельный бинарник не включает админку выдачи/отзыва пользователей: допускает клиентов, прошедших mTLS по этому CA. Для управляемого отзыва используйте встроенный gateway QUIC Lab. Серверный сертификат перечитывается на каждом новом TLS handshake; изменение CA требует перезапуска. Открытые сессии от обновления серверного сертификата не сбрасываются.

Адрес и DNS имя demux — endpoint и TLS hostname клиента. Новый режим требует ALPN quic-lab-bond/1 и не делает неявного fallback на обычный VPN, если сервер его не поддерживает.

Внешние AWG/Xray пути ещё не подключены к Android UI: отдельный бинарник сейчас проверяется прямыми QUIC-каналами. Внешний путь должен доставлять собственный защищённый обмен клиента до demux. Конфигурация чужого VPN сама по себе не включает нашу общую сессию.
