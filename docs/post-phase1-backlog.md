# Задачи после первой фазы MVP

## POST-P1-01 — обрыв соединений при возврате Wi-Fi в режиме «все приложения»

- Статус: отложено за пределы первой фазы MVP по решению владельца от 2026-10-01. Не блокирует её приёмку; срок и включение во вторую фазу отдельно не согласованы.
- Воспроизведение: на проверенном Android/MIUI включить обычный QUIC VPN для всех приложений, открыть длительное TCP-соединение, перейти Wi-Fi → LTE → Wi-Fi. При возврате Wi-Fi TCP-соединения приложений обрываются, хотя VPN-сессия сохраняется; обрыв предшествует миграции QUIC. На других устройствах и транспортах этот эффект пока не подтверждён.
- Доказательства: текущий pre.1 и старый APK 0.7.4 с нынешним профилем/сервером воспроизводят обрыв. Режим «выбранные приложения» на pre.1 прошёл два автоматических теста; владелец подтвердил исправную работу переключения в Brawl Stars после восстановления этого режима.
- Диагностический эксперимент: исключение системного UID1000 из VPN дважды устранило обрыв. Точная причина внутри Android/MIUI пока не установлена. Такое исключение не включать молча: оно отправляет системный трафик напрямую.
- Работа: установить механизм закрытия сокетов при захвате системного трафика; найти решение либо явно настраиваемый обход с описанием маршрутизации; проверить применимость на других Android/прошивках и транспортах.
- Критерии готовности: длительные TCP-соединения и UDP-потоки переживают повторные Wi-Fi → LTE → Wi-Fi в режиме всех приложений; нет скрытого прямого обхода VPN, регрессии выбранных приложений и блокировки назначенного VPN-трафика. Любые необходимые системные исключения согласованы и видимы пользователю.

Ограничение первой фазы закреплено в [спецификации](superpowers/specs/2026-09-30-vpn-product-design.md#ограничение-первой-фазы-androidmiui) и [статусе разработки](phase1-progress.md). Отдельный дефект задержанного hedge в bond UDP этой задачей не переносится за пределы первой фазы.

## POST-P1-02 — строгая изоляция исключённых приложений от VPN (вторая фаза MVP)

- Статус: включено во вторую фазу MVP по решению владельца от 2026-10-01. Отсутствие защиты принято как ограничение первой фазы и не блокирует её приёмку.
- Угроза: приложение вне VPN может попытаться привязать сокет непосредственно к tun0/tun1 через SO_BINDTODEVICE, воспользоваться выходом VPN и узнать его публичный IPv4. Это обход политики приложений, а не расшифровка туннеля или получение ключей.
- Основание: [статья](https://habr.com/ru/articles/1088980/) и [материалы авторов](https://github.com/amnezia-tun0-fix/strict-split-tunneling-notes). Проверка нашего кода pre.2 и ветки после C2 показала отсутствие проверки владельца в обычном TUN-обработчике QUIC/HTTPS/AWG. В multiple проверка частичная: правила all/subnets и принудительный выбор DNS-профиля для порта 53 не обеспечивают строгую изоляцию. Атака на пользовательском телефоне пока не воспроизведена.
- Работа: спроектировать общий контроль допуска соединений до выбора выхода/транспорта, включая single и multiple. Неизвестный владелец не должен давать доступ к VPN; отдельно согласовать обработку системного DNS/Private DNS, жизненного цикла потоков и других пакетов, для которых UID нельзя надёжно определить. Не создавать безусловный обход проверки для порта 53. Учесть фрагментацию и ICMP при проверке границы доступа, не расширяя MVP поддержкой IPv6 или новых туннельных протоколов.
- Критерии готовности: отдельное исключённое приложение без root не получает доступ к VPN-выходу через прямую привязку к TUN по TCP/UDP, включая DNS; проверены режимы «выбранные приложения»/«все кроме выбранных», single/multiple и QUIC/HTTPS/AWG. Разрешённые приложения, системный DNS/Private DNS, длительные TCP/UDP-потоки и переключения сетей работают согласно согласованной политике. Отрицательный результат не сводить к одному таймауту: подтвердить исправность тестового пути положительным контролем.
- Смежная проверка второй фазы: при добавлении VLESS/Xray не открывать незащищённый локальный прокси для чужих приложений и не публиковать адрес VPN-сервера через исключающие маршруты. В текущем Android-клиенте эти два механизма не обнаружены; тестовый desktop SOCKS не считать частью Android VPN.
- Граница гарантии: защита от использования туннеля исключёнными приложениями; сокрытие самого факта наличия VPN не обещается. Технический проект и реализация ещё не выполнены.
