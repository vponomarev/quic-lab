# AmneziaWG в Android-клиенте

AmneziaWG доступен как в отдельном профиле стороннего сервера, так и в общем профиле QUIC Lab вместе с QUIC/HTTPS. Echo-стенд сохранён. Опциональный AWG-сервер включается установщиком: [инструкция](install-server.md#опциональный-сервер-amneziawg).

## Импорт и запуск

1. Откройте настройки VPN → **Импортировать профиль .json / .conf**, выберите файл и подтвердите импорт. Также можно сканировать QR с текстом `[Interface]` / `[Peer]`.
2. Создаётся отдельный профиль с транспортом **AmneziaWG**. Старые профили остаются на месте. Профиль можно переименовать.
3. Выберите All apps / Only selected apps / Exclude selected apps / Network routing. Общий и индивидуальный списки приложений работают как прежде.
4. Запустите VPN с главного экрана или из настроек. Первое разрешение Android на VPN подтверждается вручную.

Закрытый ключ и PSK находятся только в зашифрованном файле профиля с ключом из Android Keystore. Они не записываются в SharedPreferences, диагностику или APK. Резервное копирование данных приложения отключено. Исходный импортированный файл остаётся у его владельца: приложение его не удаляет.

Комплексный профиль выдаётся через «QR QUIC Lab» или JSON в админке. После импорта
в настройках транспорта доступны только протоколы, разрешённые администратором.
Один профиль хранит и mTLS-сертификат, и AWG-ключи в зашифрованном хранилище.
Смена транспорта требует остановки и повторного запуска VPN. Изменения разрешений
на сервере применяются сразу, для обновления списка в клиенте нужен новый импорт.

## Поддерживаемый формат

Первая версия импортирует один `[Interface]` и один `[Peer]`, IPv4 Address (с префиксом или без), один IPv4 DNS, PrivateKey/PublicKey, необязательный PresharedKey, Endpoint, AllowedIPs, PersistentKeepalive, MTU 1280–1420, Jc/Jmin/Jmax/S1/S2 и числовые H1–H4. Это формат конфигов AWG первого поколения. Дополнительные параметры новых версий AWG, несколько peers и команды PostUp/PostDown явно отклоняются, а не игнорируются.

IPv4 AllowedIPs ограничивают назначения внутри ядра. Конфиг с `0.0.0.0/0` по умолчанию использует All apps; набор отдельных подсетей — Network routing. Настройка маршрутов Android может сузить набор, но не расширить AllowedIPs. IPv6 из конфига не активируется; Android блокирует IPv6 для трафика, захваченного этим IPv4 VPN. В режиме Network routing сохраняется системный DNS.

Обрабатываются TCP и произвольные UDP-потоки, включая DNS. Это адаптер потоков поверх общего TUN, а не прямое перенаправление всех IP-протоколов: ICMP приложений и multicast в данной версии не поддерживаются. На профиле QUIC с v0.6.2-dev произвольный UDP передаётся через DATAGRAM; HTTPS с v0.6.3-dev поддерживает TCP и UDP поверх WebSocket/TCP.

## RTT и смена сети

RTT измеряется ICMP Echo к IPv4 адресу endpoint **через AWG-туннель**, примерно раз в секунду. Внешний DNS для регулярных проб не используется. Endpoint должен попадать в AllowedIPs и отвечать на ICMP из туннеля. Если ответов нет, RTT отсутствует; это само по себе не доказывает, что прикладной трафик не работает. При отсутствии успешных ping с самого запуска автоматическое переключение по таймауту ping не включается; события потери Android-сети продолжают обрабатываться.

При Wi-Fi ↔ Mobile меняется защищённый UDP-сокет, а криптографическое состояние и внутренняя TCP/IP-сеть сохраняются. Резервная сеть не пробуется вторым AWG-сокетом: это могло бы менять обратный endpoint у сервера. Возврат на валидированный Wi-Fi использует задержку стабильности, чтобы избегать частых переключений.

На главном экране сохранены транспорт, RTT, jitter, TX/RX, exit IPv4, информация о сетях и маркеры переходов. TX/RX — полезная нагрузка проксируемых приложений, без накладных расходов шифрования и служебных ping. Проверка exit IP остаётся отдельной HTTPS-диагностикой, как у QUIC/HTTPS.

## Архитектура и сборка

Общий Android VpnService и TUN → обработчик TCP/UDP-потоков → адаптер транспорта. AmneziaWG использует upstream `amneziawg-go`, зафиксированный на коммите `457d920a1a7d103fc7354e0ca3979e493a681d5e`, без собственной реализации криптографии. Локальная копия MIT netstack-адаптера и её изменения описаны в `internal/awg/netstack/README.md`. Библиотека gVisor общая с существующим tun2socks.

Дополнительная пользовательская TCP/IP-сеть позволяет сохранить общую маршрутизацию и подготовить границу для будущего Xray. Это имеет стоимость по CPU/памяти; сравнительный тест батареи и пропускной способности пока не выполнен. Одновременно активен один профиль; multiple и Xray ещё не реализованы.

Сборка прежняя: `scripts/build-android.ps1 -BuildApk`, Android 11+, JDK 17 и NDK из инструкции Android.

Для разработчиков: `go test -race ./mobile ./internal/awg/...` на Linux проверяет адаптер, TCP/UDP, повторное открытие сокета и остановку. Опциональный тест `TestAWGLive` читает путь к личному конфигу из `QUIC_LAB_AWG_TEST_CONFIG`; без переменной он пропускается. Конфиг не должен попадать в git. Android-тест `AwgTest` требует явного `awg_live=true`; смена сетей включается отдельно `migrate=true`.
