# Живой захват в Wireshark: Windows и macOS

Режим для учебных соединений QUIC и HTTPS/WebSocket, Echo и VPN. Используются **существующие порты**. Захват и загрузка TLS secrets идут через HTTPS админки; дополнительный входящий порт не нужен. Отладка по умолчанию выключена.

## Без установки (рекомендуется)

Распакуйте ZIP. На странице захвата создайте сессию и нажмите «Подготовить запуск». Скопируйте одноразовую ссылку из текстового поля и запустите:

```powershell
.\quic-lab-capture-cli.exe -connect "ССЫЛКА" -wireshark "D:\Tools\WiresharkPortable64\WiresharkPortable64.exe"
```

Если Wireshark установлен стандартно, параметр `-wireshark` можно опустить. PortableApps автоматически разрешается во внутренний EXE для прямой передачи stdin. Все параметры указываются перед завершением команды. На macOS:

```sh
./quic-lab-capture-darwin-arm64 -connect 'ССЫЛКА'
```

Для Intel используйте файл `darwin-amd64`. Этот режим не регистрирует схему, не сохраняет доверенный сервер и не требует админских прав. Явный `-connect` разрешает подключение к HTTPS-серверу из вручную переданной ссылки только на этот запуск; проверка сертификата и запрет redirect сохраняются. `-open` остаётся обработчиком браузерной схемы с проверкой сохранённых доверенных серверов. Билет живёт одну минуту и используется один раз; при истечении получите новую ссылку. Секреты с телефона включаются отдельным QR, как описано ниже.

## Как провести демонстрацию

1. Преподаватель входит в админку и открывает **Wireshark**.
2. Создаёт сессию **Echo** или **VPN** и нажимает **Подготовить запуск → Открыть в Wireshark**. Ссылка живёт минуту и используется один раз.
3. На Android 0.7.3-dev или новее сканирует **QR отладки**, проверяет домен получателя и подтверждает экспорт TLS secrets. QR не меняет адреса, профили или сертификаты. Он содержит короткую HTTPS-ссылку с одноразовым токеном (2 минуты). После загрузки настроек приложение отдельно запрашивает согласие на экспорт. Полученный upload-токен разрешает только загрузку секретов в конкретную сессию, а не чтение захвата.
4. Запускает **новое** Echo/VPN-соединение с обычными настройками. Режим QR должен соответствовать опыту: сравнение Echo через VPN-профиль использует режим **VPN**.
5. Переключает Wi-Fi/LTE. Wireshark показывает STREAM/DATAGRAM/ACK и PATH_CHALLENGE/PATH_RESPONSE, если они возникли в эксперименте. Для HTTPS видны TCP/TLS и WebSocket.
6. Останавливает захват в админке и/или нажимает **Выключить экспорт TLS secrets** на телефоне. На телефоне видны счётчики отправленных ключей/ошибок/пропусков. Экспорт сам прекращается по сроку QR и после завершения процесса приложения; настройка не сохраняется между запусками процесса.

Локальная запись сохраняется в `~/QUIC Lab Captures` (`%USERPROFILE%/QUIC Lab Captures` на Windows). В `.pcapng` находятся TLS Decryption Secrets Blocks, поэтому отдельный `SSLKEYLOGFILE` не нужен. Запись содержит секреты **внешнего** учебного TLS/QUIC-соединения: HTTPS внутри VPN остаётся отдельно зашифрованным. Собственный VPN-протокол QUIC Lab не становится HTTP/3; отдельного диссектора его внутренних сообщений пока нет.

Для HTTPS Echo TLS обычно завершается в nginx. Поэтому для единого сценария QUIC/HTTPS источником секретов служит Go TLS-клиент на Android. Загружается только материал новых соединений выбранного типа с указанным TLS hostname. Закрытые ключи сертификатов не передаются. Загрузка асинхронная, с ограниченной очередью и без ожидания в TLS handshake. Capture stream задерживается примерно на две секунды, чтобы секреты успели прийти. При большой задержке загрузки скачайте завершённую запись из админки: её секреты помещаются перед пакетами.

## Сервер

Linux, `tcpdump` с поддержкой `--immediate-mode`. Debian 12/13 и Ubuntu 22.04/24.04 поставляют подходящий tcpdump:

```sh
sudo apt-get install tcpdump
```

В существующий admin JSON добавьте:

```json
"capture": {
  "interface": "any",
  "slots": 2,
  "tcpdump": "/usr/bin/tcpdump"
}
```

Путь уточните через `command -v tcpdump`. Порты QUIC/VPN берутся из действующих аргументов сервера. Порт HTTPS Echo берётся из поля `echo.https` (`host:port`); если поле отсутствует, используется порт `public_url` или 443. Дополнительные слушатели и правила firewall не создаются. Пока поддерживается IPv4, как в VPN-клиенте.

Процессу сервера нужен `CAP_NET_RAW` для tcpdump. Для systemd добавьте **отдельный** drop-in, сохранив существующие настройки:

```ini
# /etc/systemd/system/quic-lab.service.d/30-capture.conf
[Service]
AmbientCapabilities=CAP_NET_RAW
```

Если свой unit ограничивает `CapabilityBoundingSet`, добавьте CAP_NET_RAW в его разрешённый набор, сохранив нужные ранее capability. Произвольный sudo сервису не требуется. После изменения конфига нужны `systemctl daemon-reload` и перезапуск сервиса, который прервёт текущие подключения.

В **существующем location админки** nginx добавьте служебный заголовок. Он должен перезаписывать входящее значение:

```nginx
proxy_set_header X-Quic-Lab-Peer "$remote_addr:$remote_port";
```

Так сервер узнаёт внешний TCP endpoint локального компонента и исключает его из всех захватов. Это предотвращает запись передачи самой записи через тот же TCP/443. Без заголовка подключение capture через HTTP loopback proxy отклоняется. Для прямого HTTPS используется настоящий `RemoteAddr`; заголовки клиента игнорируются.

Для WebSocket нужны также `proxy_http_version 1.1`, Upgrade/Connection и `proxy_read_timeout 60s` или больше. Штатная админка уже использует WebSocket для статистики. После правки проверьте `nginx -t`, затем reload nginx.

Чтобы загрузки установщиков работали из админки, скопируйте архивы `quic-lab-capture-windows.zip` и `quic-lab-capture-darwin.zip` в `<data_dir>/downloads/capture/` с правом чтения сервису. Для отключения удалите `capture` из JSON, отдельный drop-in capability и перезапустите сервер.

## Windows: установка преподавателю

Скачайте и распакуйте `quic-lab-capture-windows.zip`. Wireshark устанавливается отдельно. В PowerShell:

```powershell
powershell -ExecutionPolicy Bypass -File .\install-windows.ps1 -Server https://lab.example/lab/
```

Установка только для текущего пользователя: `%LOCALAPPDATA%/QUIC Lab Capture`, схема `quic-lab` в `HKCU/Software/Classes`. Администратор Windows не требуется. Обработчик запускается по клику; постоянной службы и расширения браузера нет.

Для portable или нестандартной установки Windows добавьте параметр:

```powershell
powershell -ExecutionPolicy Bypass -File .\install-windows.ps1 -Server https://lab.example/lab/ -WiresharkPath "D:\Tools\WiresharkPortable64\WiresharkPortable64.exe"
```

Путь сохраняется в обработчике ссылки. Для PortableApps установщик выбирает внутренний `App\Wireshark\Wireshark.exe`, чтобы передавать поток stdin напрямую. Можно указать обычный `Wireshark.exe`. Повторная установка без параметра сохраняет ранее выбранный путь.

## macOS: установка преподавателю

Распакуйте `quic-lab-capture-darwin.zip`, установите Wireshark в `/Applications`. Затем:

```sh
sh install-macos.sh https://lab.example/lab/
```

Архив содержит исполняемые файлы для Apple Silicon и Intel. Установщик использует штатный `osacompile`, создаёт `~/Applications/QUIC Lab Capture.app`, регистрирует `CFBundleURLTypes` и подписывает локальную сборку ad-hoc. Go и Xcode для установки не нужны. Это локальная учебная сборка без Developer ID/notarization; если Gatekeeper блокирует загруженный компонент, разрешите конкретное приложение через настройки безопасности macOS, не отключая проверку глобально. Регистрацию URI и окно Wireshark необходимо проверить на настоящем Mac.

Для обновления приложения сначала переместите предыдущий `QUIC Lab Capture.app` в сторону. Установщик не удаляет существующий bundle.

## Доверенные серверы и ограничения

- В установщике указывается точный HTTPS URL админки с завершающим `/`. Новый сервер можно добавить командой `quic-lab-capture -trust-server https://another.example/lab/` (на Mac бинарник внутри `Contents/Resources`).
- Ссылки с других серверов отклоняются. Redirect при передаче билета запрещён. В URL нет постоянного админского пароля, mTLS private key или TLS secrets.
- В браузере может появиться системное подтверждение открытия внешнего приложения.
- До четырёх слотов, по умолчанию в примере два; до восьми записей с учётом завершённых. Одна сессия — 10 минут, максимум 32 MiB. В админке доступны только сессии текущего входа; TLS secrets разных сессий не объединяются. Для двух преподавателей используйте отдельные браузеры/входы; logout останавливает сессии этого входа.
- Сервер хранит запись в памяти до 5 минут после предельного времени сессии. После перезапуска она исчезает. Локальный файл не удаляется автоматически: он содержит расшифровываемый учебный трафик.
- Закрытие Wireshark прекращает поток и сессию. Для нового запуска создайте новую сессию. Кнопка скачивания в админке позволяет забрать накопленную запись без локального компонента.
- PCAP включает зашифрованный трафик выбранных существующих портов, в том числе других клиентов. Расшифровываются соединения телефонов, включивших экспорт в эту сессию. Для строгого разделения сетевых метаданных двух преподавателей используйте отдельные серверы. Собственные capture stream исключены по TCP endpoint.
- AWG не использует TLS: экспорт этих секретов его не расшифровывает. Старые соединения, открытые до захвата, не восстанавливаются.

## Сборка и проверка

```sh
go test ./internal/debugcapture ./internal/admin ./cmd/capture ./cmd/server
python scripts/build-capture.py
```

Архивы: `artifacts/capture/`. Для интеграционного теста на Linux с tcpdump/CAP_NET_RAW:

```sh
QUICLAB_CAPTURE_INTEGRATION=1 QUICLAB_CAPTURE_OUTPUT=/tmp/debug-test.pcapng   go test ./cmd/server -run TestDebugCaptureRealTLS -v

tshark -r /tmp/debug-test.pcapng -d udp.port==59440,quic -d tcp.port==59440,tls   -Y 'quic.stream_data || websocket.payload'
```

Дополнительный `TestCaptureExistingPorts` проверяет действующие слушатели, HTTPS-загрузку клиентских секретов и отсутствие feedback loop при стриминге через тот же HTTPS-порт.

Тест создаёт только синтетический Echo-трафик на loopback, использует одноразовый тестовый TLS-сертификат, не читает реальные пользовательские профили. Выходной файл должен отсутствовать перед запуском.

Источники: [Wireshark pipes](https://wiki.wireshark.org/CaptureSetup/Pipes), [TLS secrets в pcapng](https://wiki.wireshark.org/TLS), [Go KeyLogWriter](https://pkg.go.dev/crypto/tls#Config).

### Проверено на устройстве

Android: инструментальный `CaptureSmokeTest` запускает новые QUIC и HTTPS Echo-соединения и проверяет передачу secrets; для него заранее помещается временный QR в `files/capture-smoke-qr.png` приложения. Тест не меняет VPN-профили. На подключённом телефоне проверены оба транспорта, Windows-компонент получил запись через существующий HTTPS-порт, tshark расшифровал QUIC и WebSocket и в live-записи, и в скачанном файле. Linux-интеграция также проверяет чтение потока через stdin tshark. Запуск графического Wireshark через зарегистрированную схему на Windows и macOS требует отдельной проверки на компьютерах преподавателей.

## Разбор сообщений QUIC Lab

Компонент автоматически загружает встроенный `quiclab.lua` только в запущенный им Wireshark. Глобальная установка плагина не нужна. В дереве пакета появляется **QUIC Lab Echo**: Request/Reply, `seq`, `sent_ns` (монотонное время клиента, не дата), ID соединения/потока, наблюдаемый сервером адрес клиента и признаки транзитной пробы. Вложенный JSON показывает исходную структуру. Один STREAM-фрейм может содержать несколько сообщений; сообщение также может пересекать границы фреймов — используется сборка QUIC-потока Wireshark.

Фильтры: `qlab`, `qlab.seq == 42`, `qlab.kind == "Reply"`, `qlab.transit == true`. Поле можно добавить колонкой через правую кнопку мыши → Apply as Column.

Для VPN QUIC DATAGRAM есть `qlabudp`: `flow_id`, `seq`, индекс и количество фрагментов, байты полезной нагрузки. Это только разбор заголовка приложения: сборки UDP-фрагментов, привязки к целевому адресу и разбора внутренних приложений пока нет. VPN STREAM и HTTPS/smux пока остаются в стандартном представлении. AWG этот диссектор не расшифровывает.

Для старой записи запустите Wireshark с файлом `quiclab.lua` из ZIP:

```powershell
& "D:\Tools\Wireshark\Wireshark.exe" -X "lua_script:quiclab.lua" -r "capture.pcapng" -d "udp.port==4433,quic" -d "tcp.port==443,tls"
```

Укажите порты из своей конфигурации. Новый захват через компонент получает их автоматически. Диссектор требует расшифрованных данных и доступен в сборках Wireshark с Lua. Автотест: `python scripts/test-dissector.py PATH_TO_TSHARK`.

API: [Wireshark Lua dissectors](https://www.wireshark.org/docs/wsdg_html_chunked/lua_module_Proto.html).
