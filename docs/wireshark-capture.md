# Живой захват в Wireshark: Windows и macOS

Режим для учебных соединений QUIC и HTTPS/WebSocket, Echo и VPN. Используются **существующие порты**. Захват и загрузка TLS secrets идут через HTTPS админки; дополнительный входящий порт не нужен. Отладка по умолчанию выключена.

## Без установки (рекомендуется)

Распакуйте ZIP. На странице захвата создайте сессию и нажмите «Подготовить запуск». Скопируйте одноразовую ссылку из текстового поля и запустите:

```powershell
.\quic-lab-capture-cli.exe -connect "ССЫЛКА" -wireshark "D:\Tools\WiresharkPortable64\WiresharkPortable64.exe"
```

Если Wireshark установлен стандартно, параметр `-wireshark` можно опустить. PortableApps автоматически разрешается во внутренний EXE для прямой передачи stdin. Все параметры указываются перед завершением команды. На macOS:

```sh
./quic-lab-capture-darwin-arm64 -connect 'ССЫЛКА'
```

Для Intel используйте файл `darwin-amd64`. Этот режим не регистрирует схему, не сохраняет доверенный сервер и не требует админских прав. Явный `-connect` разрешает подключение к HTTPS-серверу из вручную переданной ссылки только на этот запуск; проверка сертификата и запрет redirect сохраняются. `-open` остаётся обработчиком браузерной схемы с проверкой сохранённых доверенных серверов. Билет живёт одну минуту и используется один раз; при истечении получите новую ссылку. Сессионные секреты берутся на сервере при собственной TLS-терминации.

## Как провести демонстрацию

1. В админке откройте **Wireshark**, выберите Echo или VPN и начните сессию.
2. Нажмите **Подготовить запуск**, скопируйте ссылку в CLI или откройте зарегистрированный обработчик.
3. Запустите **новое** Echo/VPN-соединение. QR и экспорт с телефона больше не нужны. Старые соединения без записанного handshake могут не расшифроваться.
4. Переключайте Wi-Fi/LTE и сравнивайте STREAM/DATAGRAM/ACK, смену адреса, PATH_CHALLENGE/PATH_RESPONSE и TCP reconnect.
5. Остановите захват. `.pcapng` с TLS Decryption Secrets Blocks сохранён в `~/QUIC Lab Captures`.

## Два режима TLS

- **Терминация в QUIC Lab:** KeyLogWriter серверного Go TLS записывает секреты новых соединений только во время активного захвата соответствующих портов. Поддерживаются Echo QUIC, VPN QUIC, собственный HTTPS Echo и VPN HTTPS. Никаких изменений в телефоне не требуется.
- **Внешняя терминация (nginx/CDN):** можно записать TLS-пакеты, но их расшифровка недоступна. Приватный ключ сертификата не заменяет сессионные секреты TLS 1.3. UDP QUIC, завершающийся в QUIC Lab, при этом расшифровывается независимо от HTTPS.

Страница захвата показывает возможности каждого слушателя. Загрузка клиентских TLS secrets и старые QR-endpoint отключены (HTTP 410). Закрытые ключи сертификатов не попадают в capture. Внутренний HTTPS через VPN остаётся отдельно зашифрованным; QUIC Lab не становится HTTP/3.

**Область захвата:** это серверная диагностика выбранных портов, включая подключения других клиентов. Все активные сессии захвата одного слушателя получают его новые TLS secrets. Разные входы в админку разделяют доступ к записям, но не изолируют трафик на общем слушателе. Для независимых преподавателей и строгого разделения используйте отдельные учебные серверы. AWG не использует TLS и этим способом не расшифровывается.

## Сервер

Установите `tcpdump` и включите в admin JSON:

```json
"capture": {"interface": "any", "slots": 2, "tcpdump": "/usr/bin/tcpdump"}
```

Сервису нужен `CAP_NET_RAW`. Если он слушает TCP/443, сохраните также `CAP_NET_BIND_SERVICE`. Не удаляйте другие необходимые capability из своего unit. Capture stream использует существующий HTTPS-порт; дополнительных публичных портов нет. Запись ограничена 10 минутами и 32 MiB, хранится в памяти до 5 минут после предельного времени сессии. Выход из админки останавливает её захваты.

Если HTTPS админки завершается в nginx, в его существующем location `/lab/` необходимы поддержка WebSocket и заголовок:

```nginx
proxy_set_header X-Quic-Lab-Peer "$remote_addr:$remote_port";
```

Он исключает передачу самой записи из capture. При прямом TLS QUIC Lab использует настоящий RemoteAddr и не доверяет этому заголовку. Порт HTTPS Echo берётся из `echo.https`, а при отсутствии — из `public_url`. Порты QUIC/VPN берутся из аргументов запуска. Поддерживается IPv4 capture.

## QUIC Lab перед существующим nginx

Эта миграция выполняется явно: штатный установщик не переносит чужие virtual hosts автоматически.

- QUIC Lab получает `-https-listen :443 -tls-host lab.example -tls-fallback 127.0.0.1:9443`.
- HTTPS virtual hosts nginx переводятся с публичного 443 на `listen 127.0.0.1:9443 ssl;`. Порт 80 и HTTP-01 webroot остаются у nginx.
- SNI `lab.example` завершается в QUIC Lab. Другие SNI и соединения без SNI передаются в nginx как исходный TLS-поток. Их сертификаты и TLS secrets остаются у nginx, не попадают в серверный экспорт QUIC Lab.
- Fallback разрешён только на literal loopback IP. Для такого проксирования nginx видит peer как loopback; PROXY protocol пока не добавлен. Это нужно учесть, если другие virtual hosts используют ограничения по IP клиента.
- `/lab/`, `/echo`, `/vpn-demo/` обслуживаются приложением напрямую. `/tunnel` доступен на общем порту, только если `-gateway-https` совпадает с `-https-listen`; отдельный существующий mTLS-порт также можно сохранить.

Перед миграцией сохраните nginx/unit, проверьте занятость loopback-порта и перечень доменов; после — `nginx -t`, каждый домен и доступ к ACME challenge. У systemd последующий drop-in может переопределить ExecStart: проверяйте `systemctl cat quic-lab`.

## Обновление сертификата без разрыва соединений

Systemd `LoadCredential` создаёт копии на запуске: одного SIGHUP для обновления этих копий недостаточно. Для hot reload используйте постоянную приватную папку внутри StateDirectory и приложенный `reload-certificate.py`:

```sh
sudo python3 /opt/quic-lab/reload-certificate.py --cert /etc/letsencrypt/live/lab.example/fullchain.pem --key /etc/letsencrypt/live/lab.example/privkey.pem --hostname lab.example --no-signal
```

Первый запуск делает staging сертификата для уже существующего пользователя сервиса. Пара проверяется, записывается в отдельное поколение с правами 0700/0600, затем symlink `current` переключается атомарно. Сервер запускайте с:

```text
-cert /var/lib/quic-lab/tls/current/cert.pem -key /var/lib/quic-lab/tls/current/key.pem
```

Добавьте `ExecReload=/bin/kill -HUP $MAINPID`. В deploy-hook Certbot после успешного renewal вызывайте ту же команду **без** `--no-signal` (проверьте `RENEWED_LINEAGE`, чтобы реагировать только на нужный сертификат). При необходимости отдельно выполняйте `nginx -t` и reload nginx. Папка должна быть доступна сервису; закрытый ключ остаётся недоступным другим пользователям. Старые поколения сохраняются для отката.

SIGHUP загружает пару атомарно, проверяет срок и сохранение DNS-имён. При ошибке сохраняется последний рабочий сертификат. Существующие TCP/QUIC-соединения продолжают работать, новый сертификат используется для новых handshakes. Проверка ACME: `certbot renew --cert-name lab.example --dry-run`; staging-сертификат не устанавливайте вместо рабочего. Штатный установщик с LoadCredential по-прежнему использует restart на renewal, пока вы явно не переключили его на hot reload.

## Windows: установка преподавателю

Скачайте и распакуйте `quic-lab-capture-windows.zip`. Wireshark устанавливается отдельно. В PowerShell:

```powershell
powershell -ExecutionPolicy Bypass -File .\install-windows.ps1 -Server https://lab.example/lab/
```

Установка только для текущего пользователя: `%LOCALAPPDATA%/QUIC Lab Capture`, схема `quic-lab` в `HKCU/Software/Classes`. Администратор Windows не требуется. Обработчик запускается по клику; постоянной службы и расширения браузера нет.

Для portable или нестандартной установки Windows добавьте параметр:

```powershell
powershell -ExecutionPolicy Bypass -File .\install-windows.ps1 -Server https://lab.example/lab/ -WiresharkPath "D:\Tools\WiresharkPortable64\WiresharkPortable64.exe"
```

Путь сохраняется в обработчике ссылки. Для PortableApps установщик выбирает внутренний `App\Wireshark\Wireshark.exe`, чтобы передавать поток stdin напрямую. Можно указать обычный `Wireshark.exe`. Повторная установка без параметра сохраняет ранее выбранный путь.

## macOS: установка преподавателю

Распакуйте `quic-lab-capture-darwin.zip`, установите Wireshark в `/Applications`. Затем:

```sh
sh install-macos.sh https://lab.example/lab/
```

Архив содержит исполняемые файлы для Apple Silicon и Intel. Установщик использует штатный `osacompile`, создаёт `~/Applications/QUIC Lab Capture.app`, регистрирует `CFBundleURLTypes` и подписывает локальную сборку ad-hoc. Go и Xcode для установки не нужны. Это локальная учебная сборка без Developer ID/notarization; если Gatekeeper блокирует загруженный компонент, разрешите конкретное приложение через настройки безопасности macOS, не отключая проверку глобально. Регистрацию URI и окно Wireshark необходимо проверить на настоящем Mac.

Для обновления приложения сначала переместите предыдущий `QUIC Lab Capture.app` в сторону. Установщик не удаляет существующий bundle.

## Доверенные серверы и ограничения

- В установщике указывается точный HTTPS URL админки с завершающим `/`. Новый сервер можно добавить командой `quic-lab-capture -trust-server https://another.example/lab/` (на Mac бинарник внутри `Contents/Resources`).
- Ссылки с других серверов отклоняются. Redirect при передаче билета запрещён. В URL нет постоянного админского пароля, mTLS private key или TLS secrets.
- В браузере может появиться системное подтверждение открытия внешнего приложения.
- До четырёх слотов, по умолчанию в примере два; до восьми записей с учётом завершённых. Одна сессия — 10 минут, максимум 32 MiB. В админке доступны только сессии текущего входа; Захваты одного слушателя получают секреты его соединений; это не изоляция клиентов. Для двух преподавателей используйте отдельные браузеры/входы; logout останавливает сессии этого входа.
- Сервер хранит запись в памяти до 5 минут после предельного времени сессии. После перезапуска она исчезает. Локальный файл не удаляется автоматически: он содержит расшифровываемый учебный трафик.
- Закрытие Wireshark прекращает поток и сессию. Для нового запуска создайте новую сессию. Кнопка скачивания в админке позволяет забрать накопленную запись без локального компонента.
- PCAP включает зашифрованный трафик выбранных существующих портов, в том числе других клиентов. Расшифровываются новые соединения выбранного слушателя с собственной TLS-терминацией. Для строгого разделения сетевых метаданных двух преподавателей используйте отдельные серверы. Собственные capture stream исключены по TCP endpoint.
- AWG не использует TLS: экспорт этих секретов его не расшифровывает. Старые соединения, открытые до захвата, не восстанавливаются.

## Сборка и проверка

```sh
go test ./internal/debugcapture ./internal/admin ./cmd/capture ./cmd/server
python scripts/build-capture.py
```

Архивы: `artifacts/capture/`. Для интеграционного теста на Linux с tcpdump/CAP_NET_RAW:

```sh
QUICLAB_CAPTURE_INTEGRATION=1 QUICLAB_CAPTURE_OUTPUT=/tmp/debug-test.pcapng   go test ./cmd/server -run TestDebugCaptureRealTLS -v

tshark -r /tmp/debug-test.pcapng -d udp.port==59440,quic -d tcp.port==59440,tls   -Y 'quic.stream_data || websocket.payload'
```

Дополнительный `TestCaptureExistingPorts` проверяет действующие слушатели, экспорт серверных секретов без клиентского keylog и отсутствие feedback loop при стриминге через тот же HTTPS-порт.

Тест создаёт только синтетический Echo-трафик на loopback, использует одноразовый тестовый TLS-сертификат, не читает реальные пользовательские профили. Выходной файл должен отсутствовать перед запуском.

Источники: [Wireshark pipes](https://wiki.wireshark.org/CaptureSetup/Pipes), [TLS secrets в pcapng](https://wiki.wireshark.org/TLS), [Go KeyLogWriter](https://pkg.go.dev/crypto/tls#Config).

### Проверка

`TestCaptureExistingPorts` использует только серверные KeyLogWriter: клиенты не выгружают ключи. `ServerCaptureSmokeTest` проверяет Echo на Android с выключенным экспортом. Проверки SNI подтверждают прямую терминацию и passthrough; тест reload проверяет сохранение последней валидной пары.

## Разбор сообщений QUIC Lab

Компонент автоматически загружает встроенный `quiclab.lua` только в запущенный им Wireshark. Глобальная установка плагина не нужна. В дереве пакета появляется **QUIC Lab Echo**: Request/Reply, `seq`, `sent_ns` (монотонное время клиента, не дата), ID соединения/потока, наблюдаемый сервером адрес клиента и признаки транзитной пробы. Вложенный JSON показывает исходную структуру. Один STREAM-фрейм может содержать несколько сообщений; сообщение также может пересекать границы фреймов — используется сборка QUIC-потока Wireshark.

Фильтры: `qlab`, `qlab.seq == 42`, `qlab.kind == "Reply"`, `qlab.transit == true`. Поле можно добавить колонкой через правую кнопку мыши → Apply as Column.

Для VPN QUIC DATAGRAM есть `qlabudp`: `flow_id`, `seq`, индекс и количество фрагментов, байты полезной нагрузки. Это только разбор заголовка приложения: сборки UDP-фрагментов, привязки к целевому адресу и разбора внутренних приложений пока нет. VPN STREAM и HTTPS/smux пока остаются в стандартном представлении. AWG этот диссектор не расшифровывает.

Для старой записи запустите Wireshark с файлом `quiclab.lua` из ZIP:

```powershell
& "D:\Tools\Wireshark\Wireshark.exe" -X "lua_script:quiclab.lua" -r "capture.pcapng" -d "udp.port==4433,quic" -d "tcp.port==443,tls"
```

Укажите порты из своей конфигурации. Новый захват через компонент получает их автоматически. Диссектор требует расшифрованных данных и доступен в сборках Wireshark с Lua. Автотест: `python scripts/test-dissector.py PATH_TO_TSHARK`.

API: [Wireshark Lua dissectors](https://www.wireshark.org/docs/wsdg_html_chunked/lua_module_Proto.html).
