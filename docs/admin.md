# Админка и QR-профили

Один процесс сервера обслуживает echo, VPN и админку. Echo остаётся публичным;
VPN требует клиентский сертификат. Админка включается флагом
`-admin-config /path/to/admin.json` вместе с флагами gateway из [VPN-инструкции](vpn-gateway.md).

## Настройка

Скопируйте [пример](../deploy/admin.example.json) в `/etc/quic-lab/admin.json`.
Замените домен, логин и пароль (уникальный, минимум 12 символов; заглушка не принимается).
`public_url` — внешний HTTPS-адрес с завершающим `/`, `listen` — только loopback.
Серверный сертификат получите по [инструкции Let's Encrypt](deploy-linux.md).
Порты UDP 4434 и TCP 8443 должны быть доступны клиенту напрямую; nginx завершает TLS
для админки и echo, но не для mTLS VPN listener.

Конфиг содержит пароль: храните его с правами 0600. Для systemd с DynamicUser используйте
дополнение к существующему unit:

```ini
[Service]
StateDirectory=quic-lab
StateDirectoryMode=0700
LoadCredential=admin.json:/etc/quic-lab/admin.json
```

Добавьте `-admin-config ${CREDENTIALS_DIRECTORY}/admin.json` к существующему `ExecStart`,
сохранив echo-флаги, сертификаты и нужные gateway-флаги. При переопределении команды
в drop-in сначала нужна пустая строка `ExecStart=`. Выполните `systemctl daemon-reload`
и перезапустите сервис. В управляемом режиме отдельный `-gateway-client-ca` не требуется:
админка создаёт собственный CA для клиентских сертификатов.

В HTTPS server-блок nginx добавьте:

```nginx
location /lab/ {
    proxy_pass http://127.0.0.1:8083/;
    proxy_http_version 1.1;
    proxy_set_header Upgrade $http_upgrade;
    proxy_set_header Connection "upgrade";
    proxy_read_timeout 60s;
    proxy_set_header Host $host;
    proxy_set_header X-Forwarded-Proto https;
    proxy_buffering off;
}
```

Проверьте `nginx -t`, затем reload. Ограничения выхода по подсетям по-прежнему задаются
`-gateway-allow`; маршруты Android сами по себе не являются серверной политикой доступа.
Для профиля network routing задайте `vpn.mode: 3` и IPv4 CIDR в `vpn.routes`, разделённые
пробелами или запятыми. Режимы выбора приложений настраиваются на телефоне.

## Выдача профиля

1. Без входа `/lab/` показывает QR с настройками echo, без ключей.
2. Войдите с логином и паролем из конфига. Добавьте пользователя.
3. Нажмите QR у пользователя. На Android нажмите «Сканировать QR» и подтвердите импорт.

Для VPN QR содержит одноразовую HTTPS-ссылку, действующую пять минут. Клиент получает
по ней настройки, сертификат и закрытый ключ; второй запрос уже отклоняется.
Выпуск нового QR отменяет предыдущий для этого пользователя. Токен находится во fragment
URL и не попадает в обычный access log. Сам QR до погашения даёт доступ к профилю:
показывайте его только получателю. Пароль администратора в профиль не включается.

Ключ на телефоне хранится зашифрованным с Android Keystore. Сертификат выдаётся на 90 дней.
Удаление пользователя запрещает новые подключения и закрывает его активные QUIC/WSS-сеансы.
Для новой выдачи после удаления создайте пользователя заново. Автопродления пока нет.

Под именем клиента нажмите «Изменить», введите новое название и сохраните.
Изменяется только отображаемое имя: ID, сертификат, ключ, статистика и активные
туннели сохраняются. Новое имя попадает в будущие QR-профили; уже импортированные
профили на телефонах автоматически не переименовываются. Открытые вкладки админки
получают имя через WebSocket; введённый текст в открытой форме не перезаписывается.

## Хранение и проверки

`data_dir/identities.json` содержит CA, закрытый ключ CA и клиентские ключи. Это секретная
резервная копия: права файла 0600, каталога 0700; сохраняйте её в защищённом хранилище.
Потеря CA требует перевыпуска профилей. Не редактируйте файл при запущенном сервере.

Сессия админки действует восемь часов; cookie Secure/HttpOnly/SameSiteStrict, изменения
защищены CSRF. Для входа действует ограничение частоты. Это учебный прототип с online CA,
без внешнего secret manager и аудита управления пользователями.

`go test ./internal/admin` проверяет вход, CSRF, отзыв, сохранение на диске и конкурентное
одноразовое получение профиля. Android `ProfileImportTest` проверяет разбор QR;
реальный импорт включается аргументом `-e qr_file filename.png`. `VpnLaunchTest` запускается
только явно с `-e vpn_ui true -e transport quic` (или `https`); системное VPN-разрешение
подтверждает человек. Дополнительный `-e browser true` открывает `/vpn-demo/` в Chrome.


## Статистика пользователей

На `/lab/users` отображаются активные туннели пользователя: транспорт, текущий исходный
IP и время подключения. Один сертификат может иметь несколько одновременных туннелей.
У QUIC адрес берётся из текущего соединения и меняется при миграции. HTTPS показывает
адрес TCP-соединения. Это адрес, видимый серверу (в том числе NAT); заголовки
`X-Forwarded-For` не используются. Страница получает снимок сразу и затем каждые 5 секунд по WebSocket `/lab/users/live`.
Обновляются только метрики; введённое имя и кнопки остаются на месте. При обрыве связи
клиент переподключается через 3 секунды. WebSocket требует действующую сессию
администратора и совпадение Origin; выход и истечение сессии прекращают поток обновлений.
После изменения списка пользователей в другой вкладке появляется предложение обновить страницу.
Для nginx в location `/lab/` нужны `proxy_http_version 1.1`,
`proxy_set_header Upgrade $http_upgrade` и `proxy_set_header Connection "upgrade"`;
таймаут `proxy_read_timeout 60s` достаточен для пятисекундного интервала.

TX — байты от клиента, RX — байты к клиенту, сумма по всем туннелям пользователя за
последние 10 минут. Окно состоит из 600 секундных интервалов. Считается TCP payload
и DNS с двухбайтовым обрамлением сообщений, без VPN keep-alive, служебного согласования,
TLS/QUIC/WebSocket-заголовков и повторных передач. Это объём, а не скорость линии.
Счётчики хранятся в памяти и обнуляются при перезапуске; последнее подключение,
его транспорт и последний известный IP сохраняются в `identities.json`. До первого
подключения после обновления отображается «Ещё не подключался». Время показывается в UTC.
Публичный echo-стенд не имеет пользовательских mTLS-идентичностей и в эту статистику не входит.


## APK на странице лаборатории

В конфиге админки укажите необязательное поле:

```json
"apk_path": "/var/lib/quic-lab/downloads/quic-lab.apk"
```

После изменения конфига перезапустите сервис. Если APK существует и доступен сервису
для чтения, под QR настроек echo появится ссылка «Скачать QUIC Lab для Android» с размером.
Кнопка «Показать QR для скачивания» раскрывает отдельный QR прямой ссылки на APK;
по умолчанию он скрыт. Загрузка `/lab/download/quic-lab.apk` публичная, без входа.
Обслуживается только заданный файл, каталог с идентичностями не публикуется.
APK рассчитан на Android 11+ и 64-битные ARM64 / x86-64 устройства.

Соберите APK через `scripts/build-android.ps1 -BuildApk`, скопируйте
`android/app/build/outputs/apk/debug/app-debug.apk` и `scripts/publish-apk.sh` на сервер,
затем выполните (нужен пакет `unzip`):

```sh
sudo sh publish-apk.sh app-debug.apk /var/lib/quic-lab/downloads/quic-lab.apk
```

Скрипт проверяет ZIP и AndroidManifest, заменяет APK атомарно и выводит SHA-256.
Сервис должен иметь право прохода к каталогу и чтения файла. Последующие обновления APK
не требуют перезапуска сервера. Используйте один и тот же ключ подписи для обновлений
уже установленного приложения и увеличивайте Android `versionCode` для новых выпусков.
Конфигурацию сервера студенты импортируют через QR; клиентские сертификаты не вшиваются в APK.
