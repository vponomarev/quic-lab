# WEB-управление MDM-устройствами

Дата: 2026-10-08. Статус: проект для проверки владельцем.
Дополнение к 2026-10-04-client-management-design.md и существующему плану mdm-core.

## Цель и границы итерации

Администратор настраивает каждый свой телефон из браузера, не беря телефон в руки после первоначальной привязки и выдачи прав. Список приложений (название и package ID) передаётся при разрешении config; пользователь явно согласовал это 2026-10-08. Управление независимо от используемого VPN-сервера и работает при выключенном VPN.

В объём входят связь с пользователями в админке, QR/ссылка в Android, состояние телефона, редактор его конфигурации, список приложений и команды VPN. Телеметрия сохраняет действующие настройки. Массовые конфигурации пользователя, remote helper, временные сеансы редактора и карты остаются последующими этапами.

## Основа и выбранный подход

Используем существующий независимый MDM-канал, ConfigurationDocument schema 1, SetDesired с проверкой revision, очередь команд с TTL, encrypted AtomicFile и авторитетные Android readers. Сейчас MdmRuntime намеренно не исполняет desiredConfig/commands, а очистка внешней конфигурации не подключена к runtime. Включение WEB-управления требует завершить эти части, а не только добавить формы.

Альтернативы: редактор одного JSON быстрее в реализации, но неудобен для ежедневной работы; новая отдельная система управления дублирует готовые хранилище и канал. Выбран обычный редактор поверх существующей модели с переиспользованием валидатора.

## Пользователь и MDM-устройство

- MDM binding получает необязательную серверную ссылку на стабильный ID пользователя VPN. Это организационная связь, не зависимость авторизации MDM от VPN-ключей.
- Приглашение из карточки пользователя сохраняет этот ID на сервере; при регистрации связь наследуется. Клиент не назначает произвольного владельца.
- Существующее устройство можно назначить пользователю или отвязать в админке. Изменение аудируется. Совпадение модели телефона не является доказательством идентичности.
- Устройства без пользователя остаются в общем разделе MDM. Удаление пользователя очищает организационную связь, не удаляет MDM и его историю. Отзыв VPN-ключа сам по себе не отзывает независимую MDM-привязку.
- Список пользователей показывает ссылку «MDM: N». Карточка пользователя содержит вкладку MDM: название, версия клиента, активность/пауза, последняя связь, последнее измерение, переход к устройству и создание приглашения.
- «Активно» означает включённую привязку; доступность определяется отдельно по последней синхронизации. Старую телеметрию нельзя выдавать за присутствие онлайн.

## Подключение на Android

Настройки → Управление устройством: «Сканировать QR» и «Вставить ссылку». Обе операции доступны с работающим VPN и используют существующий строгий парсер приглашений. При открытии показываются сервер, режим и права; сама ссылка не выдаёт согласие.

Сохраняется одна привязка: при существующей привязке показывается текущий сервер и объяснение, что для другого сервера нужно удалить старую. Сканирование не заменяет её автоматически. Ошибки QR/ссылки не меняют VPN-профили. Обычный импорт VPN остаётся отдельным действием.

## Снимок состояния телефона

Добавить версионированный аутентифицированный отчёт MDM: имя/версия клиента, поддерживаемые функции, фактическое состояние VPN, применённая ревизия и отдельный счётчик поколения локальной конфигурации. Отчёт настроек и inventory отправляется только при активном MDM с правом config. Минимальные сведения для управления VPN требуют соответствующего права vpn.

Inventory содержит название и package ID приложений, доступных Android для выбора VPN. Передаются полный актуальный снимок при первой выдаче config, затем изменения по хешу; снятие права прекращает обновления. Предыдущие сведения отображаются как устаревшие и недоступные для нового применения без права. Полнота списка явно указана: ограничения видимости Android не должны превращаться в молчаливое удаление выбранных пакетов.

Конфигурационный снимок исключает закрытые ключи, токены регистрации/обновления, MDM-секреты и credential-bearing URI. WEB знает о наличии учётных данных, сохраняет их через существующую семантику отсутствующего identity. Новые ключи/профили администратор может передать явно; сохранённые секреты не возвращаются обычным GET и не попадают в аудит. Поля разбираются по явному разрешённому набору, не через выгрузку всех preferences.

## Редактор устройства

Вкладки: Обзор, Конфигурация, Приложения, Телеметрия, События. Обзор показывает владельца, права, связь и версии, фактическое состояние VPN, очередь применения. Редактор содержит подключения/транспорты и выходы, IPv4-маршруты, выбранные приложения, резервные сети, LTE-бюджет, DNS и существующие допустимые диагностические настройки. Неподдерживаемые клиентом поля блокируются с пояснением; отсутствующие поля не сбрасываются неявно.

Приложения: поиск по названию/package ID, выбранные пакеты и обозначение не найденных на телефоне. Получение нового inventory не изменяет выбор. Все изменения остаются черновиком до «Применить». Перед отправкой виден список изменённых параметров и предупреждение, если потребуется переподключить VPN.

Разделять наблюдаемую конфигурацию и желаемую: обновление отчёта телефона не перезаписывает черновик или отправленную ревизию. При Apply проверяются базовая серверная revision и поколение наблюдаемой конфигурации. Конфликт требует перечитать изменения, без молчаливой перезаписи. Устаревшие локальные редакторы Android также не могут перезаписать удалённое применение.

## Применение и команды

Полный документ валидируется на сервере и телефоне до изменений. Для работающего VPN допустимо краткое переподключение. Единый координатор сериализует локальные Start/Stop, удалённые команды, применение и pause/delete. Явный локальный Stop во время применения не отменяется автоматическим рестартом.

Атомарная конфигурация и журнал незавершённой операции переживают гибель процесса. При ошибке валидации/сохранения прежняя конфигурация сохраняется. Успешное сохранение настроек и успешный запуск VPN — разные результаты: ошибка соединения отображается отдельно, не выдаётся за потерю конфигурации. Подтверждение revision отправляется только после устойчивого сохранения; повторная доставка не вызывает повторного применения.

Состояния WEB: ожидает доставки, применяется, применено, ошибка; отдельно показывается «VPN не подключился». Пауза/отзыв права явно блокирует исполнение. Телефон офлайн получает последнюю конфигурацию при возвращении. После паузы старые команды не исполняются, настройки актуализируются согласно ранее принятому контракту.

Команды только vpn_start/vpn_stop, с существующим TTL 5 минут, epoch и дедупликацией. Результат показывает ожидание, выполнение, ошибку или истечение срока. Отсутствие системного согласия Android на VPN требует действия на телефоне и отображается как причина отказа; WEB не обходит диалог ОС. Действия пользователя также передаются серверу.

Режим current сохраняет изменения при паузе/удалении MDM. External снимает управляемую конфигурацию и возвращает личную, включая согласованный переход активного VPN. Восстановление очистки после аварии обязательно до включения runtime-применения. Сервер не может возобновить локально приостановленный MDM или выдать права вместо владельца.

## Доступ, аудит и совместимость

Администратор использует существующую авторизацию WEB, CSRF и проверку конкретного binding. API телефона проверяет binding/secret/epoch и фактические права перед выполнением, в том числе после ожидания сети. Входные размеры ограничены; значения имён/пакетов экранируются. Нет shell-команд, установки приложений, произвольного файлового доступа или выдачи Android-разрешений.

История действий — 90 дней по ранее принятому контракту. События содержат ID, время, источник, ревизию и код результата, без секретов. Телефонные и серверные метки времени различаются. Старые клиенты продолжают телеметрию; управление скрыто/заблокировано до объявления поддержки, показывается необходимость обновления. Миграция старых binding не требует перепривязки или включения согласий.

## Приёмка

1. MDM из карточки пользователя попадает в его список; назначение старого устройства и независимые устройства работают. VPN-ключи не дублируются.
2. QR и текст открывают одинаковое подтверждение без выключения VPN; чужое/повторное приглашение не заменяет существующую привязку.
3. Inventory появляется только с config; названия, Unicode, отсутствующие пакеты и ограничения видимости обрабатываются корректно.
4. Из WEB меняются DNS, приложения, резерв/бюджет, маршруты и профиль. Проверяется фактическая конфигурация и передача трафика, а не только надпись в WEB.
5. Проверены конфликты двух редакторов, offline, повтор доставки, пауза/удаление/отзыв права во время apply, процессная авария на этапах транзакции, current/external и восстановление личного состояния.
6. Start/Stop и локальный Stop конкурируют предсказуемо; TTL и epoch предотвращают исполнение старых команд. Отказ Android отображается явно.
7. Регрессия обычного VPN, телеметрии и обновления APK. Go/race на Linux 192.168.5.214; Android через Windows ADB на тестовом Redmi; финальная проверка разрешённых операций на Note12Pro. Непроверенные версии Android явно отмечаются.
8. После прохождения проверок — сервер, APK и доступность обновления на quic-demo.vpnc.ru; состояние реализации и результаты фиксируются в документах.
