# Редактирование MDM с телефона

Пользователь просит разрешаемое администратором редактирование: телефон отправляет
правку серверу, сервер сохраняет новую MDM-ревизию и провижинит её обратно.
Прежнее разрешение на автономную разработку сохраняется. 2026-11-05 пользователь
явно подтвердил полный объём права: вся VPN-конфигурация, включая профили и импорт.
Права MDM и административные разрешения остаются у администратора.

В настройках конкретного MDM-устройства администратор включает отдельное право
`userConfigEdit`, по умолчанию false. Оно не входит в предоставляемые телефоном
согласия Rights и не может быть изменено через документ или device API. Ревизия
права защищает черновик от отзыва и последующего повторного предоставления.

Подходы: разблокировать локальные preferences нельзя — получится обход серверной
версии. Перенос всех native экранов в распределённую транзакцию затрагивает импорт,
профили, несколько выходов и настройки одновременно. Выбран отдельный редактор
MDM на телефоне с существующими формами web-редактора, упакованными в APK. Локальный
WebView не загружает удалённые страницы; узкий native bridge выполняет только
чтение и сохранение конфигурации своей MDM-привязки через физическую сеть.

Редактор работает с отдельным черновиком; VPN/runtime не меняется при вводе.
Сохранение проверяет active binding/epoch, config consent, серверное право,
ревизию права, desired revision и report generation. Повтор имеет request ID;
потерянный ответ не создаёт вторую ревизию. Ошибка/отзыв/конфликт сохраняет черновик
и требует перечитать состояние для новой правки. Неприменённая серверная ревизия
блокирует новую правку. Применяет только существующий MdmApplyCoordinator.

Разрешено менять VPN profiles/settings, routing/apps, DNS, budget, reserve,
diagnostics и research scope в рамках существующих согласий. Mode current/external
и административная profileSelection policy сохраняются сервером. При разрешённом
удалении профиля сервер удаляет только его ссылки из profileSelection, не добавляет
новые разрешения. Права MDM, enrollment/secret и административные настройки
не редактируются. Старые ключи не выдаются редактору; новые принимаются write-only.

Транспорт: bounded TLS POST device endpoints config-editor/config-submit; epoch,
permission revision и revision/generation проверяются атомарно с записью. Аудит
отличает actor=user от admin и не сохраняет содержимое конфигурации в событиях.
Административные формы защищены существующими session/CSRF/Origin проверками.
Старый сервер не поддерживает capability, старый телефон остаётся read-only.

Проверки: deny-by-default, чужой binding/token, pause/epoch, отзыв/regrant,
одновременная admin/device правка, retry, save failure/reopen, policy protection,
secret redaction, desired→sync→phone apply. Android build/lint, targeted Note9
tests и WebView rendering; полный Go suite/race на разрешённом Linux-хосте.
Go tests на Windows не запускать. Без production deploy, push или merge.
