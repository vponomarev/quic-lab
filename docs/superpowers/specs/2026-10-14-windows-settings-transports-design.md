# Windows: редактор подключения и подсетей, затем AWG/VLESS

Дата: 2026-10-14. Статус: согласована схема в чате; документ подготовлен к проверке владельцем.

## Цель и порядок

Владелец хочет менять настройки Windows VPN и список IPv4-подсетей через GUI, затем подключаться к сторонним AWG/VLESS-серверам. Текущей версии Windows достаточно для приёмки. Сначала выпускаем проверяемый редактор QUIC/HTTPS, затем последовательно добавляем AWG и VLESS. Выбор приложений, MDM, исследовательский сбор, kill switch и гарантированное восстановление после сна остаются вне этой итерации.

## Интерфейс

Главное компактное окно сохраняет состояние, подключение/отключение, TX/RX и скорость. Кнопка «Настройки» открывает отдельное изменяемое по размеру окно с разделами «Подключение» и «Подсети». Длинные формы прокручиваются внутри этого окна, основные действия остаются видимыми.

В этой итерации редактируется одно сохранённое подключение. Каталог нескольких подключений не является условием завершения. Название и транспорт видны в главном окне. Для QUIC/HTTPS доступны адрес, порт, имя сервера/TLS, сертификат клиента, ключ и необязательный CA. Ключи скрыты; сертификаты и ключ можно заменить из файла. Незаполненное поле скрытого секрета означает «оставить прежнее», замена задаётся отдельным явным действием. Не выводить ключи в статус, исключения или журналы. Настройка физического интерфейса находится в дополнительных параметрах с понятным названием адаптера; текущий выбор сохраняется.

Список подсетей: таблица CIDR, добавить, изменить, удалить, вставить несколько строк. Изменения сначала образуют локальный черновик. Проверка показывает конкретную строку и причину: неверный IPv4/CIDR, адрес вместо начала сети, повтор или пересечение, запрещённая сеть, захват адреса сервера. Нормализацию предлагает явно, без незаметного расширения маршрута. На первом этапе сохраняется действующий предел 16 непересекающихся подсетей. IPv6 и маршрут по умолчанию пока не поддерживаются; ограничения видны в форме. Пустой список не применяется.

«Сохранить» проверяет настройки на стороне службы. При работающем VPN появляется выбор «Сохранить и переподключиться» или «Отмена». Нет неявного сохранения при закрытии. Вопрос о несохранённых изменениях появляется только при изменении значений. Ошибки сохранения и подключения различаются. Если новый корректный профиль не подключился, он остаётся сохранённым, VPN показывает ошибку; автоматического переключения на другой профиль нет.

## Служба, хранение и применение

Текущий backend фиксирует Settings при запуске службы, а apply_config поддерживает только старую модель тестового backend. Расширяем контракт реального профиля, не подменяя применение успешным ответом тестового пути.

GUI работает через существующий аутентифицированный named pipe. Отдельные операции читают редактируемое представление без секретов, валидируют черновик и сохраняют его с ожидаемой ревизией. Новые команды объявляются capability; старый UI продолжает start/stop/status, новый UI объясняет необходимость обновления старой службы. Чужой пользователь Windows не получает управление профилем.

Служба — единственный автор сохранённого профиля. Секреты защищены существующим DPAPI/ACL механизмом; GUI не передаёт службе произвольные пути для привилегированного чтения. Пользовательские файлы читаются в GUI с ограничением размера и передаются как содержимое. Схема настроек строгая, без произвольных аргументов процессов, команд оболочки и конфигураций стороннего движка.

Применение сериализуется с Start/Stop. Сначала полная проверка, затем остановка и подтверждённая очистка собственного адаптера/маршрутов, затем атомарное сохранение и замена backend; при запросе — запуск. Неудачная очистка запрещает замену. Ошибка записи оставляет предыдущую сохранённую ревизию, UI сообщает остановленное состояние. Параллельный устаревший редактор получает конфликт ревизии. Статус показывает сохранённую и активную ревизии, чтобы не выдавать сохранение за подключение.

Первый запуск новой службы импортирует прежний защищённый engine.json, сохраняя профиль и секреты; дальнейшие перезапуски читают новое хранилище. Повторной миграции поверх пользовательских изменений нет. Исходник миграции остаётся в защищённом каталоге до отдельной процедуры очистки. Обновление службы требует UAC, обычное редактирование владельцем — нет.

## AWG и VLESS

Транспортные адаптеры подключаются к общему жизненному циклу, маршрутам и статистике. Список подсетей является настройкой клиента, не диктуется импортированным конфигом. Серверный endpoint разрешается через физическую сеть до установки маршрутов; сокеты транспорта привязаны к физическому выходу. Если адрес сервера попадает под выбранные подсети, подключение отклоняется с объяснением. Системный DNS на первом этапе не меняется; DNS из импортированного файла не применяется молча.

AWG: импорт standalone-конфига с ключами, адресом туннеля, endpoint, peer и параметрами обфускации, поддерживаемыми имеющимся ядром. Поддерживаемые параметры проверяются; неизвестные существенные параметры не игнорируются. AllowedIPs показываются как предложение для списка маршрутов и не заменяют его без подтверждения. Неподдерживаемый default route требует явного выбора подсетей. Скрипты и команды конфигурации не выполняются. Используем существующее Go-ядро, без установки сторонней службы VPN.

VLESS: импорт vless:// через существующий строгий парсер; TCP/RAW + TLS или REALITY, поддерживаемый flow, SNI и fingerprint. UUID и параметры REALITY редактируются в соответствующих полях. WS/gRPC/XHTTP, подписки и произвольный Xray JSON не входят в этот шаг: неподдерживаемая ссылка возвращает понятную ошибку. TCP/UDP проверяются на отдельном совместимом сервере; факт поддержки VLESS не означает поддержку любого публичного профиля.

Существующий QUIC/HTTPS ICMP v2 специфичен для нашего сервера. Его нельзя отправлять сторонним AWG/VLESS-серверам. AWG ICMP проверяется как IP-трафик; VLESS не объявляется поддерживающим ping/tracert без отдельной реализации. Отсутствие ICMP не маскируется локальными успешными ответами.

## Проверки и критерии завершения

Редактор: существующий профиль мигрирует без потерь; чтение/изменение/отмена работают; перезапуск GUI и службы сохраняет результат; ошибки полей понятны; секреты не возвращаются в status. Проверить конфликт ревизии, запись с ошибкой, Start одновременно с Apply, отказ очистки, доступ другого пользователя. Проверить компактное главное окно и форму с длинным списком.

Реальная сеть: менять только согласованные тестовые подсети, подтверждать маршрут и трафик через выбранный выход, сохранение остальных маршрутов и DNS, Stop и уборку адаптера. Приёмка редактора на QUIC/HTTPS предшествует транспортам. Для AWG и VLESS отдельно проверить импорт, TCP, UDP, счётчики, неверные ключи/недоступный сервер, отмену подключения, повторный Start/Stop, сохранение настроек и уборку после отказа. Для VLESS отдельно TLS и REALITY. Go race/протокольные тесты на Linux; сборка и native/service/UI проверки на текущем Windows. Результаты фиксируются отдельно по транспорту; кросс-сборка не заменяет сетевой тест.
