# VLESS subscriptions and Linux client — autonomous iteration
Date: 2026-10-16. User requested autonomous implementation, Android testing when available, then Linux on test host. Routine design decisions are made here without requiring an absent user's reply.

## Subscription design
Android first: named HTTPS subscription, explicit refresh and confirmation. Accept newline VLESS URIs and standard/base64url encoded lists, at most 1 MiB and 256 entries. Existing VLESS validator is authoritative; unsupported entries counted and shown, never interpreted as arbitrary Xray code. Empty/all-invalid responses fail without mutation. No automatic background refresh in this initial implementation.
Store URL (a credential) encrypted in the existing configuration runtime, never logs. Deterministic per-subscription profile IDs derive from endpoint/security/server-name identity excluding password/UUID and fragment, allowing key rotation and renaming. Colliding identities reject ambiguity. Keep local routing/app rules and current selection; show additions/updates. Missing remote entries are retained until explicit user deletion. At most 32 imported+existing profiles; fail whole update if capacity exceeded. Refresh after deleting an imported profile can recreate it, as documented.
Use a TransferPreview and LocalConfigurationApply to preserve existing transactional apply, generation checks, MDM permissions and VPN lifecycle. Subscription metadata participates in the same encrypted runtime commit. Only explicit save changes settings; fetch is asynchronous, TLS checked, no redirects, time/size bounded, no raw errors containing URLs.

## Linux design
A real CLI client using shared gateway/transport engine and Linux TUN, initially QUIC/HTTPS with IPv4 subnet routing. No desktop environment is available on test host: GUI, MDM and app routing are later work. CLI runs foreground under root/systemd, accepts protected JSON, creates uniquely owned ephemeral TUN; iproute2 command arguments never shell-interpolated. Explicit endpoint outside captured subnets and existing foreign route conflicts reject start. No default route/full capture in first CLI milestone; IPv6 and DNS unchanged. SIGTERM closes packet input before gateway teardown and removes owned TUN/routes. Never modify physical default route. Provide validate mode, package/install instructions and service template. Test real TCP/UDP over QUIC/HTTPS in isolated network namespaces on 192.168.5.214, including signal cleanup and host management route unchanged. Additional transports are follow-up until individually tested.
