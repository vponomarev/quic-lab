# Linux GUI implementation plan

Execution: inline, using executing-plans and TDD; autonomous work authorized.
Goal: native desktop control of the existing Linux service and four profiles.
Spec: ../specs/2026-11-11-linux-gui-design.md
Stack: Python standard library control service, PyGObject GTK 3 frontend.

## Constraints and review focus
- No profile editing, keys in UI, arbitrary paths/commands or root GUI.
- Preserve installed network helper and VPN unit/binary; closing GUI leaves VPN.
- Reject wrong socket peer, unsafe profile/config files and unknown active profile.
- A failed switch rolls back; stale invocation counters never look current.
- UI stays responsive during operations; unavailable service is not disconnected VPN.

## Tasks
- [x] Control API: desktop/linux/control.py, test_control.py. Tests first:
  whitelist/UID, safe metadata, systemctl state, counters invocation filtering,
  failed start rollback, active profile switch and malformed request rejection.
  API status/connect(profile)/disconnect/reconnect/autostart(enabled).
- [x] GUI: desktop/linux/app.py, client.py, model.py and test_model.py.
  Test counter reset/rate, reconnect state, authenticated bounded socket client.
  GTK window updates via GLib from worker; confirmation for running switch;
  offline errors keep controls disabled, window closure leaves service alone.
- [x] Packaging: packaging/linux/install-gui.sh, control unit, desktop launcher,
  icon; validate installation/uninstallation on isolated host and Xvfb GUI smoke.
- [x] Independent review, docs/linux-client-gui.md and acceptance report;
  deploy to laptop if reachable, verify network and final QUIC active/enabled;
  otherwise deliver verified installer and explicitly record outstanding live QA.
