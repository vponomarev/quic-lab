# Unified Network Analysis Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans; record evidence and keep future stages explicit.

**Goal:** Объединить декодирование и данные разных источников, сохранив локальный DNS для будущей маршрутизации.
**Architecture:** Чистое общее ядро, протокольные адаптеры, наблюдения с источником, серверное объединение и независимые потребители.
**Tech Stack:** Go/gomobile, Kotlin, существующие JSONL/HTML и x/net/dnsmessage; без новых зависимостей.
**Spec:** [Согласованная архитектура](../specs/2026-10-11-unified-network-analysis.md).

## Global Constraints
Go-тесты только на Linux 192.168.5.214. Android/ADB через Windows. Исследовательский сбор off by default; локальный декодер не имеет побочных эффектов. Production и телефоны не обновлять в этой подготовительной итерации. Не суммировать разные источники/уровни байтов. Старые записи читаются без выдуманного происхождения.

## Review Focus
Поддельный origin от клиента; переполнение DNS counts/compression; потеря TTL/CNAME/class; двойной учёт после обновления старого клиента; отсутствие разрешения на исследование не должно мешать локальному разбору.

## Результат итерации A — 2026-10-11

Реализованы типизированный ограниченный DNS-декодер, использование его мобильным сборщиком, origin/received_at, принудительная маркировка клиентских записей сервером, совместимая дедупликация и отображение происхождения в админке. Новые значения схемы для серверных источников зарезервированы; адаптеры B–D пока отсутствуют.

Проверки: RED новых тестов подтверждён на Linux до реализации; `go test -race` для netobserve/research/gateway/admin прошёл. Первый общий mobile race-прогон дал таймаут `TestBothPathsTemporarilyUnavailable`; пять отдельных повторов и повторный полный mobile race-набор прошли (53.537s). Причина одиночного таймаута не установлена; не выдаём повторный успех за исправление этого теста. Android AAR, assembleDebug, assembleDebugAndroidTest и lintDebug — успешны. SVG отрисован Chromium и проверен визуально. Независимое ревью кода — без замечаний.

На телефоны и production эту подготовительную итерацию не устанавливаем. Следующий шаг — B: серверный наблюдатель QUIC/HTTPS и точная связь app metadata с серверным logical flow.

## Исполнение B — 2026-10-11

Ruling: расширение открытия потока передаёт только непрозрачные session/flow ID, в том числе до включения исследования; это не разрешение на сбор и не имя приложения. Это позволяет включить/отозвать сбор на уже открытом потоке без переподключения. Без подтверждённого consent control сервер не собирает данные. Сервер назначает собственный flow ID, а клиентский ID хранится отдельной ссылкой — повтор ID не склеивает серверные потоки.

Ruling: первый серверный счётчик измеряет успешный I/O внешнего logical connection, а не доставку приложению. Записи клиента сохраняются отдельно; автоматическое сложение запрещено. UDP DNS разбирается общим ядром; TCP DNS reassembly остаётся отдельной задачей.

- [x] B1: версия расширения, точная связь потоков TCP/UDP (QUIC DATAGRAM / HTTPS / bond), старые peers без изменений.
- [x] B2: ограниченный асинхронный наблюдатель server_gateway; delta раз в минуту/close, UDP DNS, consent generation и пропуски.
- [ ] B3: регрессии и приёмка; объединение приложения с серверными фактами по явной ссылке.

## Дополнительная регрессия B3 — 2026-10-11

- [x] Linux, реальные QUIC + HTTPS bond-пути: оба порядка подключения, потеря первого пути, один выходной TCP-сокет и стабильный UDP mapping. Серверные наблюдения сохраняют точные client_flow ссылки; TCP/UDP байты не удваиваются, UDP — ровно два датаграммных обмена.
- [x] Через оставшийся путь: отзыв generation 2, отклонение запоздавшего generation 1, продолжение TCP при выключенном сборе, возобновление generation 3 на том же TCP-потоке. В отчёт входят только байты после возобновления.
- [x] Пересоздание ResearchReceiver и повторное открытие дискового Store: старый flow ref не даёт согласия, новое control-согласие включает сбор; серверные epoch/record ID не конфликтуют, происхождение, received_at и клиентская ссылка сохранены после чтения истории.

Проверки на 192.168.5.214: новые bond/restart race-тесты x10 прошли; полный `go test -race ./internal/gateway ./mobile -count=1` прошёл (mobile 54.748s). После расширения проверки дискового восстановления весь gateway race x3 прошёл. Изменения этой итерации — тесты и документация; поведение продукта не менялось.

Ruling: тест пересоздания receiver/store проверяет границу серверного жизненного цикла, но не имитирует аварийное завершение процесса или потерю последнего незаписанного окна. Linux bond проверяет реальные транспорты на loopback, но не радиоусловия телефона. Поэтому B3 полностью не закрываем: остаются физические два пути/переключения, перезапуск процесса стенда и повтор на Note12. Production и телефоны в этой итерации не изменялись.

- [x] Bond на Note12: финальные 7/7 (301.721s), обязательная проверка двух ready Wi-Fi paths для QUIC и HTTPS. Два HTTPS TCP-сокета также подтверждены на сервере через ss. Шесть контрольных потоков точно совпали: QUIC TCP 19928/19928, UDP 46/46, DNS 29/61; HTTPS TCP 20352/20352, UDP 47/47, DNS 29/61.

Harness получил явный аргумент `research_bond=true`. Пул из трёх слотов нужен на этом локальном стенде, поскольку при доступном LTE один слот резервируется под сотовую сеть; два слота остаются Wi-Fi. Не приравнивать настройку pool_size=2 к двум готовым Wi-Fi-путям.

Ограничения/найденные особенности: первый запуск не достиг стенда при выключенном Wi-Fi; Wi-Fi временно включён, в конце выключен. Первый bond-прогон 7/7 не подтверждал два готовых пути, поэтому повторён с assert. Строгая старая проверка «ровно три потока» не учитывала существовавшие при включении согласия DNS-сокеты: они корректно отмечены incomplete и проверены отдельно. В первом bond-прогоне такие граничные записи включали 82 входящих UDP-байта и 24 исходящих TCP-байта; в финальном — два нулевых DNS-потока. Шесть полностью наблюдавшихся синтетических потоков сверены отдельно без отбрасывания их байтов.

Исходные current profile и multiple mode сравнены с приватной резервной копией и восстановлены. Тестовые креды удалены. Службы VPN/MDM работают; уведомление подтверждает LTE/AWG и MDM/GEO. Проверка пользовательского трафика после восстановления не выполнялась. Note9 и production не изменялись; на Note12 установлен внутренний debug APK 0.9.4-pre.2 (58), публичного релиза не было.
