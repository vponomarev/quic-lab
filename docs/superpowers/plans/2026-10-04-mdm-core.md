# MDM Core — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Администратор добровольно привязанного Android-клиента управляет конфигурацией и VPN независимо от наличия собственного VPN-сервера; пользователь сохраняет немедленные паузу и удаление MDM.

**Architecture:** Независимый Go-модуль MDM в общей серверной установке, отдельная Android-служба управления и локальный контроллер полномочий. Версионированный снимок настроек применяется через единый адаптер существующих конфигов, а разовые команды доставляются отдельно. Существующий managed VPN profile не считается MDM-привязкой.

**Tech Stack:** Go, существующий HTTP/admin stack, Kotlin/Android API 30–35, Android Keystore, AtomicFile, HTTPS long polling; без новой базы данных и без второй VpnService.

**Spec:** [Принятая спецификация](../specs/2026-10-04-client-management-design.md), принята владельцем 2026-10-04.

Статус: план подготовлен для проверки владельцем; реализация не начата. Пакет 1 из 4. Выполнять последовательно своими силами; отдельное решение о делегировании не требуется для подготовки этого документа.

## Global Constraints

- Одна MDM-привязка на телефон; пауза сохраняет её, смена сервера требует удаления.
- Регистрация только после явного согласия; обычный VPN QR не включает MDM.
- Команды по умолчанию действуют 5 минут. Возобновление не исполняет старые разовые команды.
- Пауза немедленная и локальная; уведомление серверу — до трёх попыток в пределах одной минуты.
- Current сохраняет изменения после паузы/удаления; external удаляется вместе с рабочими копиями, восстанавливает личные настройки без автоматического запуска VPN.
- Offline сохраняет конфиг и VPN; boot/unlock восстанавливает активную службу MDM, но сам по себе не запускает VPN.
- Пользователь и сервер равноправно переключают VPN; локальные права проверяются непосредственно перед действием.
- Нет shell, произвольного кода, файлового доступа или установки APK по команде MDM.
- Администратор и отдельное устройство — первый объём; группы и личный кабинет позже.
- Права на геоданные, координаты и LAN раздельны. В этом пакете нет их сбора или передачи.
- Серверная история — 90 дней по умолчанию; управление учитывает общий жёсткий бюджет приложения.
- Не менять приёмку первой фазы VPN и не трогать устройство текущего длительного теста. Не снижать поддерживаемое число устройств ниже 30.

## Review Focus

1. Пауза одновременно с ответом сервера/применением: поздний callback не возвращает полномочия или внешний конфиг (задачи 3, 4).
2. Сбой процесса между сохранением команды и её результатом: не повторять переключение VPN и не сообщать вымышленный успех (задача 5).
3. Повторная регистрация после потери HTTP-ответа: одно приглашение не создаёт несколько устройств и не оставляет клиент без ключа (задачи 1, 3).
4. Повреждение/нехватка места при записи многопрофильного конфига: никаких частично применённых настроек или потери личных ключей (задача 4).
5. Отсутствие разрешения VPN/запрещённый запуск фоновой службы на новой Android: видимый отказ, управление не выдаёт ложный статус «VPN включён» (задачи 2, 5, 7).

## Границы и технические решения

Включены регистрация, права, lifecycle, команды, два режима конфига, минимальная админка и экран MDM. Отдельные будущие планы: телеметрия/трекинг; перенос конфигов/временный браузерный редактор; remote helper/агент. Минимальная админка этого пакета редактирует конфиг конкретного MDM-устройства, а не предоставляет временную сессию редактора без привязки.

Предлагаемые технические лимиты этого плана: одноразовое приглашение 24 часа; 32 случайных байта токена; тело API до 1 МиБ; long poll до 25 секунд; reconnect backoff 1–60 секунд с jitter. Очередь событий управления на телефоне: 24 часа или 1 МиБ, явный счётчик пропусков; сервер: не более 100 ожидающих команд на устройство, переполнение отклоняется. Дедупликация команд хранится до expiry плюс 24 часа; время сверяется с сервером, длительности считаются монотонно. Эти лимиты не заменяют будущий буфер телеметрии 24 часа/50 МиБ.

HTTPS со стандартной проверкой имени/цепочки, минимум TLS 1.2 для MDM; совместимость TLS 1.0 Web UI не распространяется на MDM API. Токены только в Authorization/POST, не в access log или query. Приглашение: `quiclab://mdm/enroll#<base64url-json>` с HTTPS endpoint и одноразовым token; Android всегда показывает нормализованный hostname перед подтверждением. Не следовать перенаправлениям с учётными данными. Секрет устройства генерируется клиентом до redeem; сервер хранит hash. Повтор redeem с тем же registration ID и секретом возвращает ту же привязку; с другим — отказ.

Поколение управления (`epoch`) выдаёт сервер при activate/resume, инвалидирует все ранее выпущенные команды; на Android отдельный локальный `generation` увеличивается при паузе/удалении/смене прав. Ответ может примениться только при совпадении обоих значений и активном состоянии. При resume сначала новый epoch и последняя конфигурация, затем новые команды. На сервере хранится только одно активное поколение на binding.

## Карта файлов и контрактов

Новые Go-файлы `internal/mdm/{types,store,enrollment,control,http}.go` отвечают за DTO, атомарное хранилище, регистрацию, очередь/ревизии и device API. Новые `internal/admin/mdm.go`, `mdm.html`, `mdm.js` — авторизованный UI. Новый `cmd/server/mdm.go` — подключение модуля и management-only режим.

Новые Android-файлы в `android/app/src/main/java/ru/vpnc/quiclab/`: `MdmModels.kt`, `MdmStore.kt`, `MdmController.kt`, `MdmTransport.kt`, `MdmService.kt`, `MdmBootReceiver.kt`, `MdmConfiguration.kt`, `MdmVpnControl.kt`, `MdmActivity.kt`, `MdmEnrollActivity.kt`. Не разносить обычные настройки VPN в новую систему без совместимого адаптера.

Wire DTO version=1 (Go types и Kotlin модели с одинаковыми JSON полями): `Binding(id, epoch, requestedRights)`, `Rights(config, vpn, telemetry, geo, coordinates, lanMode)`, `ConfigRevision(revision, mode, document)`, `Command(id, bindingId, epoch, issuedAt, expiresAt, kind)`, `Event(id, actor, kind, commandId?, revision?, result, occurredAt)`, `SyncRequest(epoch, appliedRevision, events)`, `SyncResponse(epoch, desiredConfig?, commands, serverTime)`. ID строковые случайные, revision/epoch положительные int64; mode `current|external`; kind команд строго `vpn_start|vpn_stop`; lanMode `deny|confirm|allow`. Вложенный document определяет задача 4. Неизвестные версии/операции отклоняются, неизвестные необязательные поля игнорируются без выдачи прав.
