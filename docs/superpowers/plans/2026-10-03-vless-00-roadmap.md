# Android и Linux VLESS — план реализации

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Выпустить Android VLESS и управляемый Linux VLESS-вход, затем подключить внешние профили к общей demux-сессии.

**Architecture:** Встроенный Xray-core за Go-адаптером на Android; отдельный управляемый Linux-процесс с тем же ядром. Существующий HTTPS/bond получает соединение через адаптер VLESS, сохраняя внутреннюю аутентификацию и общую сессию.

**Tech Stack:** Go, Xray-core, gomobile, Kotlin, существующие gateway/bond/vpnmodel/admin, systemd.

**Spec:** ../specs/2026-10-03-android-vless-design.md

Статус: план для согласования. Версию Xray и окончательные внутренние API фиксируем результатом V0; V1–V5 — последовательность поставок, их пошаговые планы составляются после технического контроля. Не выполнять будущие задачи по непроверенным предположениям.

## Global Constraints

- Android 11+, IPv4, Linux/systemd; Windows отложен.
- Нет открытого локального прокси, скрытого direct fallback или глобального переключения сети движка.
- TCP/RAW + TLS/REALITY/Vision сначала; WS и XHTTP — расширение матрицы, затем подписки.
- Сохранять политику выходов, резервов, карусели, бюджетов и отзыв устройств.
- Go-тесты/бинарники на Linux 192.168.5.214; Android-сборка/ADB на Windows. quic-demo.vpnc.ru разрешён как отдельный сетевой стенд.
- Реальные секреты подписки и тестового сервера только в artifacts либо закрытом серверном каталоге. Не включать их в команды тестов, snapshots, Git или журналы ошибок.
- Существующие сервисы quic-demo не перенастраивать; стенд имеет отдельные порты и ограниченный срок работы.

## Review Focus

- Внешний профиль содержит routing/balancer или цепочку: импорт не изменяет его смысл молча (V1).
- DNS движка создаёт дополнительный сокет: protect/bind и бюджет распространяются на него (V0).
- Закрытие/пересоздание пути одновременно с подключением: старое поколение не оживает (V0/V3).
- Удаление VLESS UUID блокирует только новые handshakes: требуется закрыть активные TCP/UDP устройства (V0/V2).
- TLS/REALITY несовместимы с выбранной версией/fingerprint: диагностика отличает отказ авторизации от отсутствия сети, без вывода секретов (V0/V4).

## V0 — технический контроль Xray (первая исполняемая задача)

**Files:** Create `internal/vless/engine.go`, `internal/vless/engine_test.go`, `internal/vless/socket_test.go`; modify `go.mod`, `go.sum`; create `docs/vless-compatibility.md`. Android smoke добавляется в `android/app/src/androidTest/java/ru/vpnc/quiclab/VlessEngineTest.kt` после Linux-контроля.

**Interfaces proposed for the adapter:**
- `SocketBinder interface { Bind(int64) error }` — защита и физическая сеть, ошибка закрывает сокет до connect.
- `SocketFactory interface { DialContext(context.Context, string, string) (net.Conn, error) }` — физические TCP-соединения, обёртка существующего счётчика бюджета; пакетный путь требует отдельного контракта при подтверждении UDP.
- `NewEngine(ctx context.Context, outboundJSON []byte, sockets SocketFactory) (*Engine, error)` — только предварительно проверенный одиночный outbound, без исполнения произвольного клиентского JSON.
- `(*Engine).DialContext(context.Context, string, string) (net.Conn, error)` и `(*Engine).Close() error` — совпадают с потребностью `flowDialer`; TCP обязателен, UDP получает явный результат проверки возможностей.

Это проверяемый контракт интеграции, а не утверждение, что upstream Xray предоставляет такую фабрику напрямую. Внутри адаптера допустима версия API Xray, подтверждённая исходниками. Нельзя подменять фабрику process-global сетевым переключателем.
