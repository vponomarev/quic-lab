# v0.8.0-pre.7 — исправление импорта QR с VLESS

Android versionCode 27.

При сканировании QR QUIC Lab с включённым VLESS экран подтверждения обращался к отсутствующему полю `vless` вместо `vless_uri` и завершал приложение с `JSONException: No value for vless`. Новый профиль не сохранялся, поэтому после обновления сервера пользователь продолжал подключаться к старым портам.

Теперь подтверждение корректно показывает адреса всех транспортов, включая VLESS, без UUID или URI с credentials. Ошибка формата ответа обрабатывается в UI без падения приложения.

Установщик сервера автоматически обновляет уже включённый AWG worker без повторного `--enable-awg`. Это устраняет несовместимость старого worker с подтверждением сохранения протоколов (`AWG worker reload unavailable`).

Проверено: воспроизведение исходного падения и новый регрессионный тест на подключённом Redmi Note 12 Pro; после исправления 18 Android-тестов импорта/совместимости прошли, assemble и lint успешны. Опциональный сетевой QR-тест без fixture не выполняет регистрацию. Для установщика прошли 57 Linux-тестов. На production проверено сохранение VLESS у пользователя с AWG.

На подключённом телефоне исправлены старые адреса QUIC/HTTPS на порт 443; QUIC через LTE подключается, передаёт трафик и определяет exit IPv4 через туннель. Повторное сканирование QR для добавления нового профиля теперь не падает на VLESS.

[Скачать APK](https://quic-demo.vpnc.ru/lab/download/quic-lab.apk). Для профилей со старыми портами обновите конфигурацию или повторно импортируйте QR.
