# Максимальная доступность — проект и реализация

Статус: экспериментальный прототип 0.8.0-dev; автоматические и базовые проверки на телефоне пройдены; проверка при постепенном ослаблении сигнала ещё требуется. Публичный релиз не подготовлен.

## Контракт
Один TUN, одна логическая VPN-сессия, два независимых аутентифицированных QUIC-канала на существующем mTLS порту. Echo и обычная миграция остаются прежними. HTTPS/AWG в первой версии не объединяются.
Пользователь явно включает режим с предупреждением о расходе LTE и аккумулятора, включая погашенный экран. Приоритет Wi-Fi, резерв LTE. Переживаем потерю любого канала, но не состояния серверного процесса. Нулевая пауза не гарантируется.

## Протокол
Каждая сессия привязана к клиентскому сертификату и случайному 256-битному секрету присоединения. Сервер проверяет доступ при подключении каждого канала. Секрет не пишется в логи. Сессия хранит соединения с адресатами независимо от внешних соединений. После полного отсутствия путей 30 секунд завершается явно, а не создаёт незаметно дубли потоков.
Записи содержат тип, flow ID, порядковый номер, ID записи и временную метку попытки. Приём подтверждается только после помещения в ограниченную очередь. Порядок обеспечивается отдельно для каждого потока. Повтор открытия/FIN не создаёт новое действие.
UDP не превращается в надёжный поток: ограниченная копия, срок актуальности 200 мс, окно удаления дублей. Фрагментация существующего UDP mux переиспользуется.
Доставка идёт через QUIC DATAGRAM; контроль перегрузки остаётся у QUIC. Размер записи ограничен 1050 байтами плюс заголовок. Не более 64 неподтверждённых записей на поток, 1024 на сессию. Очереди приёма также ограничиваются. Нет безлимитного накопления при обрыве.

## Планировщик
Порог подстраховки адаптивный: RTT + 4×вариация + запас, с нижним и верхним пределом. Превышение — повод безопасно отправить копию, а не доказательство потери. Wi-Fi после сбоя должен пройти период устойчивой работы; повторные сбои откладывают возврат. Проверки обоих каналов при отсутствии подтверждаемого трафика. Планировщик действует в обе стороны.

## Обязательное до выпуска
- отдельные счётчики LTE: полезные данные, проверки, копии, включая приём; счётчик провайдера может отличаться;
- бюджет подстраховки отдельно от общего жёсткого лимита LTE, синхронизация ограничений с сервером;
- график очереди неподтверждённых записей, спасённых блоков, дублей/просроченных UDP, RTT обоих путей, отметки событий; подробная диагностика выключена по умолчанию;
- тесты ошибок сети: потеря ACK, переупорядочивание, обрыв пути, общий обрыв, возвращение Wi-Fi, captive portal, медленный читатель, лимиты памяти, отзыв сертификата;
- сценарий квартиры/лифта/подъезда на телефоне, включая выключенный экран;
- серверные ограничения числа сессий, время жизни, корректное закрытие и очистка;
- автоматический запрет режима в несовместимых профилях, без скрытого downgrade.

## Реализовано в прототипе
- независимое ядро internal/bond и защищённый адаптер internal/bondquic;
- два QUIC соединения, общая сессия, TCP half-close, остановка ненужной передачи после закрытия читателя;
- недоставка одного потока не завершает соседние потоки; ограниченные очереди;
- повторная доставка и удаление дублей, для UDP срок повторной отправки 200 мс (не гарантия возраста уже находящегося в сети пакета);
- адаптивная подстраховка, Wi-Fi probation с ограниченной пробной передачей перед полным возвратом, проверка задержки относительно LTE;
- mTLS + секрет присоединения, привязка к сертификату; 32 общие сессии на сервер, до 4 на сертификат;
- встроенный gateway и отдельный cmd/demux;
- Android: явное включение для одного QUIC-профиля, два активных пути даже при погашенном экране; Multiple явно отклоняет несовместимый режим;
- график неподтверждённых записей, спасённых TX, истекшего UDP, текстовая статистика RTT/TX/RX/повторов/служебного обмена по путям;
- бюджет упреждающих копий и лимит LTE на запуск VPN, запрет LTE сохраняется после автоматического восстановления логической сессии.

## Учёт и ограничения первой версии
Счётчики относятся к записям протокола, включая его заголовки; они не учитывают внешний QUIC/IP, handshakes и повторы внешнего транспорта. Это не биллинговый или месячный лимит оператора. Общий лимит записей LTE делится поровну между направлениями; это консервативное ограничение, не динамическое перераспределение бюджета. При исчерпании серверной доли клиент получает запрет при следующем присоединении пути. При ручном Stop/Start начинается новый бюджет. Месячный постоянный учёт требует отдельного этапа.

Бюджет упреждающих копий не запрещает необходимые повторы надёжного потока. Если основной канал сломан, новые полезные данные идут через LTE и не считаются накладными копиями. Лимит LTE ограничивает также эту передачу.
После 65536 открытых потоков логическая сессия больше не принимает новые: ID не переиспользуются, чтобы поздний OPEN не создал второе соединение. Автоматическая ротация сессий после опустошения потоков — доработка перед длительным production-использованием.

## Следующая проверка с телефоном
Обновить сервер и APK, включить режим в QUIC-профиле. Проверить физическую привязку путей, Wi-Fi → LTE → Wi-Fi, погашенный экран, captive portal. Затем маршрут квартира → лифт → подъезд → удаление от дома с TCP-загрузкой и real-time UDP. Сравнить паузы и накладной LTE с обычным QUIC. Поддержка сторонних AWG/Xray underlay и TCP-only адаптера пока не реализована; контракты описаны в bond-layers.md.

## Проверка на устройстве — 2026-09-30
На Android прошёл инструментальный сценарий: оба физических пути активны, отключение Wi-Fi, возврат Wi-Fi и краткое выключение экрана. Идентификатор логической сессии сохранился. Это не проверка длительного Doze или маршрута квартира/лифт.
Сервер и тестовый APK обновлены. После разрешения установки отдельного генератора проверено одно HTTPS/TCP-соединение через VPN и транзит: 352 запроса за 45 секунд, один сокет без повторного подключения, максимальное время запроса 178 мс. Внутри сценария Wi-Fi отключался и возвращался, экран гасился. В финале pending=0; зарегистрирована доставка через резервный путь. Это результат одного короткого прогона, не SLA и не оценка расхода батареи.

Первый вариант теста на внутренний адрес сервера не подходил: выход через удалённый транзит не имел маршрута к этому адресу. Тест заменён HTTPS-запросами на существующий публичный порт; временный внутренний echo остановлен и удалён. Настройки профиля и Wi-Fi восстановлены.

Тест: BondDeviceTest, отдельное debug-приложение :probe (сборка с -PwithProbe). Параметр probe_host задаёт разрешённый тестовый HTTPS-хост; путь /bond-connectivity-test должен возвращать ограниченный ответ с Content-Length и поддерживать HTTP/1.1 keep-alive. Настройки и список приложений тест сохраняет и восстанавливает.
